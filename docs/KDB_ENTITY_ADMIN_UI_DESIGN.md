## 1. 일상 메뉴는 5개

| 메뉴 | 운영자가 하는 일 | 기존 자산과 연결 |
|---|---|---|
| 개요 | 미분류/동명/권리/언어 결손을 구분하고 필요한 작업으로 이동 | 기존 home 실제 집계를 확장, 합성 수치를 운영 통계로 사용 금지 |
| 고유명사 | 유형·복수 직업·분야·등록일로 검색, 신규 등록, ID별 상세 | 현재 common catalog/registration 재사용 |
| 검수 | 동명 비교·분류·표기·권리 문제의 전후값/근거 확인 | 기존 mapping/후보 검수 통합 진입 |
| 보충 | 요청 언어 준비/원인·재시도·Gemma 목적과 비용 확인 | 기존 preparations/workflow 재사용 |
| 설정 | 언어·사전/원천 정책·권한 관리 | 고급 변경은 관리 권한과 감사 필수 |

TDB sources/scout/agents/lanes 등 메뉴를 1:1 복제하지 않는다. 이전 원장·batch·복구/SQL 진단은 운영자 전용 고급 도구에 둔다.
메뉴 수를 줄여도 권리·철회·원본 출처·정정 이력은 상세/검수에서 볼 수 있어야 한다.

## 2. 핵심 화면과 전이

```text
고유명사 목록 → 신규 등록 → 유형/세부유형 + 복수 직업/분야 + 근거
                              ↓ 동명 후보가 있을 때
                        후보 비교(각 UUID)
                       ↙        ↓        ↘
                  기존 선택   별개 등록    보류
                       ↓        ↓        ↓
                    해당 UUID 상세 / 검수함
                             ↓
                  정확 locale 준비 / 제한 보충
```

목록 열: 이름, 유형, 직업/세부유형, 복수 분야, 소속/지역, 짧은 ID, 분류 상태, 최근 갱신.
짧은 ID는 표시용이며 상세/복사/저장에는 전체 UUID를 사용한다.
검색은 별칭도 포함한다. 후보가 여러 명이면 모두 표시하며 가장 유명한 한 명만 결과로 선택하지 않는다.
상위 직군 필터는 하위를 포함하고, 분야 필터가 다른 분야 기사에서의 사용을 제한하지 않는다.

등록: 이름·유형·허용 subtype·분야·인물 복수 직업·출처를 입력한다. 모르는 값은 미확인으로 남긴다.
미확인 값으로도 후보 접수는 가능하되 분류/이름 승인과 구분한다. 등록 직후 생성된 UUID로 상세를 연다.
동명 후보 비교 후 '별개 대상 등록'을 허용한다. 같은 이름이 있다는 이유로 등록 자체를 막지 않는다.
다른 인물의 이름/프로필을 복사하는 버튼은 만들지 않는다.

상세: 기본 정보 / 언어별 표기·근거 / 소속·직업·기간 / 원본 연결 / 변경 이력.
항상 전체 UUID·writer·revision·잠금·정체성 판정을 표시한다.
원본명/별칭 변경과 동일인 병합을 분리한다. 병합은 비교→계획 미리보기→근거/이유→고위험 확인 순서다.
선택한 UUID가 바뀌면 이름·보충·근거 폼도 초기화하며 A의 입력 상태를 B에 재사용하지 않는다.

검수: classification_pending/classification_conflict/identity_ambiguous/name_unverified/rights_blocked 필터.
전후값, 각 원본의 UUID/직업/소속/지역/공식 ID, 근거 URL·주장 범위·권리 상태, 선택 이유를 보여준다.
확정·별개·보류는 명시적 버튼이다. '검수 처리됨'을 'DB 값 승인됨'과 혼동하지 않는다.

보충: 요청 단위와 Entity 단위를 전환한다. requested_locale/state/proof/실제 표기/fallback/사유/다음 재시도를 분리한다.
모델 작업 종료/이름 보유/해당 언어 실제 준비는 다른 숫자다. 야간 호출은 목적별 호출·토큰·승인 변경·준비 증가를 표시한다.
관측이 없는 비용/사용량은 '미계측'으로 표시하고 0으로 그리지 않는다.

## 3. 오류·권한·접근성

| 상황 | 화면 계약 | 서버 계약 |
|---|---|---|
| 조회 실패 | 오류+재시도, 기존 집계 시각/지연 표시. 빈 목록/0건으로 위장 금지 | 5xx와 request ID, 민감 내부 오류 숨김 |
| 결과 없음 | 필터 초기화/후보 등록 제안 | 빈 정상 결과와 장애 구분 |
| 늦은 저장/다른 탭 수정 | 409, 현재 revision/전후 차이, 재검수 안내 | 낙관 잠금, 자동 재저장 금지 |
| viewer | 조회만, 변경 버튼 비활성/숨김 | 직접 POST/PATCH도 403 |
| reviewer | 후보/근거/분류 판정, 허용 범위 수동 표기 검수 | 역할·소유자·CSRF·reason·revision 검사 |
| operator | 제한 job 재시도/취소·잠금·승인된 이관 운영 | 재시도 한도·batch 정확 대상 재검사 |
| admin | 사전/권한 관리·고위험 병합 승인 | 권리 사실을 임의로 승인할 수 있는 권한은 아님 |

모든 입력은 label, 키보드 접근, 초점 표시가 있어야 한다. 상태는 색상 외에 글자로 구분한다.
390px에서는 목록을 카드/좁은 열로 재배치하며 페이지 전체 가로 스크롤을 만들지 않는다.
1440px에서는 후보 비교와 언어 표기를 나란히 볼 수 있어야 한다.
CSRF/권한/입력 검증은 화면 버튼만으로 보장하지 않는다.

## 4. 프로토타입과 검증

[로컬 화면 시안](ui/kdb-entity-console.html)은 네트워크/API 호출 없는 합성 데이터 시안이다.
가수/배우 동명 비교, 복수 직업 필터, 8분야 접근, 상세의 UUID/locale 상태, 오류/빈 결과, 신규 후보 미리보기를 제공한다.
저장 버튼은 DB 저장을 하지 않고 제출 예정 JSON을 보여준다. '설계 시안·운영 데이터 아님' 표시를 항상 유지한다.
실제 Go API 배선/로그인·CSRF·권한·DB 저장/E2E는 P1/P6의 별도 완료 조건이다.
프로토타입에서 동작한다고 실제 관리자 UI가 바뀌었다고 보고하지 않는다.

설계 인수 사례: M01/M03/M04/M06/M11/M13/M14 + 390/1440px + 오류/빈 목록 + viewer + UUID 선택 후 폼 초기화.
실데이터 검수자의 사용성 승인과 운영 UAT는 아직 남아 있다.
