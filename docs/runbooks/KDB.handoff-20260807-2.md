## §1. ★앵커 25건 검수 — 3건이 상위 시리즈였다 (6c6f239, 0108)

43차가 만든 tmdb-anchor 레인이 밤사이 백로그를 다 돌았다: **410건 처리 → 앵커 25건**.

TMDb 원본과 대조했고, **3건이 우리 작품이 아니라 상위 시리즈**였다.

### 무엇이 잘못됐나 — TMDb 는 시즌을 항목 하나로 접는다

```
tv/71908 "크라임씬"       KR alt: 크라임씬 리턴즈
tv/62411 "식샤를 합시다"   KR alt: 식샤를 합시다 2 / 식샤를 합시다 3: 비긴즈
tv/18495 "논스톱"         KR alt: 논스톱3 / 논스톱 4 / 논스톱5 / 뉴 논스톱
```

43차 커밋 메시지는 "시즌 접미사(`환승연애2`)라 TMDb 에 해당 작품이 실제로 없다"고 썼다.
**그게 틀렸다.** 있다 — 다만 **상위 시리즈 항목의 alt 표기로** 있다. 그래서 2026-07-23
Phase1 관용화(주제목 무매칭이면 alt 대조)가 시즌 엔티티를 프랜차이즈 항목에 붙였고,
tmdb-locale 이 **프랜차이즈 제목을 시즌 칸에** 써넣었다.

가장 선명한 증거: 크라임씬 리턴즈의 zh 가 `犯罪现场`(=Crime Scene)로 채워졌는데, 정작
그 항목의 CN alt 에는 시즌용 `犯罪现场归来`(=Crime Scene **Returns**)가 따로 있다.
**있는 값을 두고 틀린 값을 골랐다.**

★43차 §4.5(별칭 함정)와 같은 계열이고 한 층 위에서 재발했다. **alt 표기는 "그 이름으로도
불린다"이지 "이 항목이 그 작품이다"가 아니다.** 하루 만에 같은 착각을 다른 소스에서 했다.

## §3. CJK 경보의 98%가 노이즈였다 (1c476a8)

`active-cjk-gap` 이 1,931건을 보고하는데, **어느 레인이라도 지금 집을 수 있는 건 30건**
(1.6%)이었다. 나머지는 §2 처럼 이미 판정이 끝난 것이다.

98%가 손댈 수 없는 값인 지표는 무시되고, 그러면 진짜 30건이 묻힌다. 이 파일이
`never-examined-gap` 을 "94% 거짓"이라며 재정의한 것과 **정확히 같은 구조**다 —
그때 남긴 교훈이 바로 옆 조건에 적용되지 않은 채였다.

```
⚠ active-cjk-actionable total=30 over_60d=2 oldest=64d
  active-cjk-gap-raw     total=1931 (경보 없음, 참고값)
```

판정 여부는 `noCurrentCJKVerdict()` 로 본다 — `FillRetryPredicate` 와 같은 규칙(지문 일치
+ 90일 창). **새 CJK 레인을 만들면 `cjkFillLaneSQL` 상수에 반드시 추가할 것.** 빠뜨리면
그 레인이 판정한 항목이 영영 "미판정"으로 경보에 남는다.

## §4. 미해결 — 선행 레인이 만든 같은 계열 오염 2건

§1 의 가드는 **앞으로**를 막는다. 선행 레인이 이미 만든 것은 안 건드렸다(43차 §4.5 가
"앵커 제거는 다른 레인의 판단에도 영향을 주는 별개 결정"이라고 남긴 전례를 따랐다).

1. **`모범택시3` → tv/119769 `모범택시`, zh `模范出租车`.** TMDb API 로 확인했다 —
   주제목에 3 이 없다. 프랜차이즈 제목이 시즌 3 칸에 들어가 있다. §1 과 같은 결함이지만
   앵커를 붙인 게 tmdb-anchor 레인이 아니다(승급 드레인으로 추정).
2. **`논스톱` 엔티티 2건**(둘 다 active, 이름이 같다)이 tv/18495 에 걸려 있고 zh 가
   `男生女生向前走 第五部`(=**5기** 제목)다. §1 과 방향이 반대인 오염 — 프랜차이즈
   엔티티에 시즌 제목이 들어갔다. **엔티티가 2건 중복인 것 자체도 별건이다.**

확인 명령:
```bash
docker exec kdb-db psql -U kdb -d kdb -c "
SELECT e.id::text, e.canonical_ko, r.external_id, e.canonical_zh, e.canonical_zh_source
  FROM kwave_entities e JOIN kwave_entity_external_refs r ON r.entity_id=e.id AND r.provider='tmdb'
 WHERE r.external_id IN ('119769','18495') AND e.status='active';"
```

### 43차에서 넘어온 미해결 (아직 그대로)

**`제이(ENHYPEN)` 의 ja `eaJ` 가 `correction-verified`(사람 검증 표시)인데 틀렸다.**
그 표시를 신뢰해 온 다른 판단들이 있으므로 단독으로 고치지 말고, 같은 표시가 붙은 값들의
신뢰도를 함께 점검해야 한다. 43차·44차 연속으로 못 했다.

## §5. 손댈 수 없는 것 — CJK 천장 확정

세 경로를 전수 실측했고 전부 바닥이다. **이건 결함이 아니라 측정된 사실이다.**

|---|---|---|
| 위키데이터 레이블 | 소진 | nothing-new 1,248 (43차 §3) |
| TMDb | 소진 | no-match 384 / 앵커 수율 5% (§1) |
| 구글번역 + 게이트 | 소진 | bad-title 2,232, 게이트 유지 결정 (§2) |

agency 129 · channel_outlet 99 · brand_place 80 · character 45 는 **권위 출처가 존재하지
않는다.** 여기에 기계번역을 붓지 말 것.

**새 아이디어를 내려면 다른 출처군**(OTT 카탈로그·배급사 보도자료·음반사 메타데이터)을
가져와야 한다. 기존 세 경로를 다시 파는 건 이미 측정된 낭비다. 가장 큰 덩어리인
song_album 458건은 MusicBrainz 경로가 `status='candidate'` 전용이라 §1 과 같은 사각지대가
남아 있는데, **MusicBrainz 가 한국 음반의 CJK 표기를 실제로 갖고 있는지는 아직 측정 안
했다** — 레인을 만들기 전에 표본 100건으로 수율부터 재라. TMDb 에서 8% 기대하고 5% 나온
전례가 바로 이 세션이다.
