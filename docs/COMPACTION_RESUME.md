## 1. ★ 운영자가 준 규칙 (절대 잃으면 안 된다)

1. **한 사람/한 대상 = 하나의 ID.** 겸업으로 ID 를 쪼개지 않는다. ID 가 갈리는 유일한
   이유는 **다른 대상**이라는 것이다. → [식별 계약 §1.1](KDB_IDENTITY_CONTRACT.md)
2. **흡수할 때 ID·분류·구분값을 함께 부여한다.** 구분되지 않으면 **지어내지 않고 검수로**.
3. **wikidata QID 는 보조다.** 자체 ID 가 주 앵커다.
4. **관측이 먼저, 흡수가 나중.** 관측하지 않은 값을 지어내지 않는다(D-37).
5. **권리 판단은 운영자 몫.** 운영자가 "사용 가능"이라 한 것을 내가 게이트로 막지 않는다.
6. **AI 가 스스로 판단해 작동하는 시스템이다.** 없던 사람 승인 단계를 만들지 않는다.
7. **다른 사이트 컨테이너는 절대 건드리지 않는다.** (2026-09-14 명시 지시)

## 7. 실측이 잡아낸 내 오판 (같은 실수 반복 금지)

1. **"적재 비계 880MB 정리"** — 681MB 는 비계가 아니라 흡수분의 **자체 ID 앵커**
   (`basis_record_id`)였다. FK 세 개가 `ON DELETE RESTRICT`.
2. **`tourapi_ko 12` → 관광지** — 문서 기억으론 맞지만 이미 분류된 2,033건 중
   **heritage 1,170 · nature 739**. 세부 일치율 57.6%. 코드는 "장소다"까지만 말한다.
3. **`shared_buffers` 4GB 권고** — 가용 메모리를 재보고 1GB 로 철회했다.
4. **"3분에 3건 오류"** — `--since` 를 잘못 걸어 재시작 **전** 로그를 보고 있었다.
5. **③과 ④를 이어 붙이면 브랜드 12개가 사라진다** — 각 스크립트는 옳은데 이어 붙이면
   지키려던 대상을 잃는다. 스크립트 하나씩만 읽어선 안 보이는 자리다.
6. **⑤를 그대로 돌리면 ④를 되돌린다** — 범위 밖으로 뺀 45,734건에 분류 근거를 다시 쌓을
   뻔했다. "각 단계가 맞다"가 "이어 붙여도 맞다"를 뜻하지 않는다.

**전부 그럴듯했고 전부 틀렸다.** 기억·직관이 아니라 데이터에서 도출한다.

8·13·14 는 한 덩어리다: **검증 장치 자체를 검증하지 않으면 통과가 통과가 아니다.**

15. **"P4.02 는 여행 출처를 연결하는 일"이라고 읽고 시작했다** — 재어 보니 표기는 이미
   전부 들어와 있었고(en 341,796·ja 303,379), 충돌도 0건이라 규칙도 필요 없었다.
   막고 있던 것은 **출처가 아니라 대상 상태 두 가지**였고, 그것을 여는 코드 경로가
   wikidata 만 받아 자체 ID 앵커라는 계약 자신의 원칙과 어긋나 있었다.
   **과제 제목이 가리키는 곳과 실제 병목이 다를 수 있다.** 제목을 믿고 짓지 않고 먼저 쟀다.
16. **수요 기반 규칙이면 대상을 고를 수 있다고 봤다** — 302건을 고르는데 그 안에
   `아일랜드`(소비자는 **drama** 로 보냈다)·`돈`(**movie**)·법정동 `상원` 9건이 그대로 있었다.

17. **내가 만든 활성화 도구가 결함 인물 15,009명을 열어 줬다** — 여행 대상을 기준으로 쓴
   규칙을 인물에 그대로 적용한 것이 문제였다. 여행 출처(tourapi·aihub·seoul_dict)는
   **데이터셋 단위**로 권리가 정해져 항목 식별이 근거가 아니고, wikidata 는 **항목 단위**다.
   같은 규칙이 두 출처에 다르게 적용돼야 했다. 5·6·7 과 같은 자리다 —
   **조각마다 옳은 것을 이어 붙일 때 틀린다.** 도구를 만든 당일에 그 도구를 의심해서 잡았다.
18. **"흡수분 인물의 표기가 wikidata recorded 라 좋다"고 P4.02 결론에 적었다** — 맞는 말이지만
   근거 행을 열어 보니 `source_record_id` 가 QID 가 아니라 TDB UUID 였다(65,487/65,972).
   **provider 칸이 'wikidata' 라는 것과 그 표기가 추적 가능하다는 것은 다른 말이다.**
19. **회수한 QID 를 `export_allowed=true` 로 넣었다** — 그러면 DB 트리거의 "재사용 가능한
   정체성 근거"를 **그 QID 가** 만족시켜 대상이 **QID 때문에** 열린다. 실측: 회수 434건이
   전부 `tdb export=false / wikidata export=true` — 자체 관측은 자격이 없고 외부 항목이
   문을 열고 있었다. **운영자가 "QID 는 기본이 아니라 보조"라고 짚어 줘서 알았다.**

   방금 회수한 항목 지목이 날아갔다. **플래그가 아니라 문을 여는 쪽에서 강제해야 했다** —

20. **"P5 = 동일성 판정"이라고 문서 9곳에 적었다** — P5 는 **단일 writer 전환**이고

22. **"기존 원장 보강을 공통 원장으로 흘리는 다리"를 만들려 했다** — 트리거가 막는다:
