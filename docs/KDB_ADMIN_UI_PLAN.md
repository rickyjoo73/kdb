# KDB 관리자 UI 기획 / 구현 기준

2026-09-12. 대상: `https://kdb.aiinplanet.com/admin/`.
기존 Go 서버 렌더링과 인증/CSRF를 유지하여 단계적으로 개선한다.
미구현 기능을 작동하는 것처럼 표시하거나 수치로 채우지 않는다.

상태: 1차 개요/탐색/워크플로우 개선은 `workflow-20260912-3`으로 운영 반영.
전체 상세 CRUD/권한/통합 검수함/분야별 UI는 아래 후속 범위다.

**2026-09-12 16:14 추가 운영 상태:** 아래 최초 기획 이후 `/admin/preparations`,
`/admin/kentity`, `/admin/kentity/mappings`, `/admin/kentity/tdb`를 실제 구현·배포했다.
요청 언어별 준비/근거 버전, 다중 분야 후보·자동 조사·선택 표기 검수,
기존 UUID의 공통 범위 전환·잠금, TDB ID-only 연결 비교를 제공한다.
목록/상세/빈 상태/오류/권한·보호 폼의 Go 및 390px/1440px 브라우저 검증을 통과했다.
TDB 화면은 비교 전용이며 승인/이관 완료 화면이 아니다. 전체 관리자 UAT는 아직 남아 있다.

## 핵심 운영 질문

1. 지금 실패하거나 오래 멈춘 요청은 무엇인가?
2. 작업이 끝난 것인가, 번역에 쓸 표기가 준비된 것인가?
3. 누구인지/어떤 출처인지 확실한가? 무엇 때문에 자동 처리가 보류되었는가?
4. 내가 할 수 있는 다음 조치는 무엇이며 영향을 받는 데이터는 무엇인가?

## 공통 화면 규칙

- 첫 화면은 '정상' 장식이 아니라 상태와 조치의 출발점이다. 자동 refresh로 편집을 덮어쓰지 않는다.
- 모든 수량은 범위/단위/기간을 붙인다. 요청 수, Entity 수, 필드 수, 충돌 그룹 수를 합산하지 않는다.
- attempt 종료는 준비 완료가 아니다. 값 존재는 공식 표기 검증이 아니다.
- authoritative/evidenced/unverified는 현행 Entity 등급으로 표시한다. 언어별 공식 표기 인증으로 확대 해석하지 않는다.
- 쿼리 실패는 0건으로 위장하지 않는다. 미계측·정상 빈 상태·집계 실패를 분리한다.
- 색상뿐 아니라 텍스트로 상태를 표시한다. 필터·페이지·검색 조건을 URL로 재현 가능하게 한다.
- 숫자를 클릭하면 같은 집계 조건의 목록을 여는 것이 목표다. 조건이 일치하지 않는 기존 화면에는 '전체 검토 화면' 등 범위를 명시한다.
- 명칭은 이름으로 찾아도 수정/병합은 불변 ID로 한다. 동명 검색은 복수 후보를 보존한다.
- 데스크톱은 탐색+작업 영역, 모바일은 접을 수 있는 메뉴+한 열 카드; 표만 가로 스크롤한다.
- 키보드 초점, 본문 건너뛰기, 필드 label, 현재 메뉴 표시, 색 대비를 갖춘다.

## 위험 작업 UX와 서버 요구사항 (후속)

승인/재시도/병합 버튼은 실행 전에 대상 UUID·영향받는 필드/소비자·근거·전후 차이·잠금·비용을 보여준다.
서버는 역할 권한, CSRF, 최신 버전 일치, 정책 위반 여부를 다시 검사한다.
대량 작업은 한도와 dry-run을 갖추고 감사 이벤트를 남긴다.
되돌릴 수 없는 병합은 즉시 실행하지 않고 검증된 정정/복구 절차를 먼저 구현한다.
원문 기사·검색 결과에 포함된 명령문은 정책이나 관리 권한으로 취급하지 않는다.

## 1차 수용 테스트

- 실제 수량이 있는 개요가 렌더링되고, 각 업무 링크가 기존 등록된 페이지로 연결된다.
- 큐 0건·작업 종료 0건이어도 '전 구간 정상'이나 준비 SLA 0%를 표시하지 않는다.
- DB 집계 실패 시 오류 안내와 재시도 경로를 표시하고 잘못된 0 카드는 숨긴다.
- 공식+근거를 합쳐 '공식 %'로 표현하지 않는다. 레거시 인물 수는 별도 호환 DB로 표시한다.
- 같은 입력 재시도 보류/정책 보류/유형 제외/선택 가능 필드의 합이 누락 필드 수와 맞는다.
- 390px/1440px 폭에서 메뉴·검색·본문에 접근 가능하고 숨은 메뉴 링크는 focus되지 않는다.
- 모든 기존 템플릿 smoke test와 변경된 DB 통합 테스트를 통과한다.
- 전체 UI 완성 판정은 1차 화면 배포가 아니라 실행 계획 11단계 UAT에서 한다.

## 1차 검증 결과

- 390px/1440px 합성 데이터 브라우저 테스트 통과: 검색·현재 메뉴·접기/Escape·빈/오류 상태·갱신 선택.
- 전체 Go 테스트, 변경 admin race 테스트, 복원한 운영 스냅샷 READ ONLY 화면 테스트 통과.
- 운영 HTTPS에서 정상 로그인 후 새 개요, workflow, 기존 Entity/동명이인/인물 페이지 확인.
- 개요 약 258ms, workflow 약 1.9초 (최적화 전 약 7.4초). 해당 시점 관측이며 성능 보장은 아니다.
- 이름 일치 카드가 임의의 한 Entity를 정답처럼 선택하지 않도록 검색 목록으로 연결.
- 작업 종료의 기간을 개요/워크플로우 모두 종료 시각 기준 최근 24h로 통일.
