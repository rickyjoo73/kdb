## 목적과 확정 방향

Edipresso의 기사 원문을 PressLocale에서 수신하고, 공통 Entity 자산으로
인물·기관·기업·장소·작품 등의 다국어 표기를 확정하여 번역·검증·CMS 반환까지 연결한다.
정치·경제·사회·연예·스포츠·여행이 같은 Entity를 공유한다.

1. **KDB를 운영 기반으로 점진적으로 공통 Entity 마스터로 확장한다.**
   도메인별 KDB/TDB/정치 DB 3개를 영구적으로 병렬 운영하지 않는다.
2. 기존 KDB UUID와 소비자 API를 보존한다. TDB는 검증한 매핑을 통해 단계적으로 편입한다.
   관광 전문 속성·출처 규칙은 없애지 않는다. 통합은 모든 속성을 한 테이블에 넣는 뜻이 아니다.
3. Go API·상태 관리·DB 계층을 유지한다. Python은 필요하면 독립 NER/Entity linking 작업자로 사용한다.
4. 이름 일치만으로 동명이인을 합치지 않는다. 엔티티 유형·기사 문맥·외부 ID·시간별 소속·근거를 함께 본다.
5. 모르는 표기를 추측으로 공식 DB에 승격하지 않는다. 자동 처리가 불확실하면 이유와 검수 작업을 남긴다.
6. 관리자 UI는 부가 화면이 아니라 운영 기능이다. 각 화면은 상태·근거·조치·이력을 제공한다.

## 실행 규칙

- 단계마다 구현 → 자동 테스트 → 필요한 실데이터 읽기 검증 → 제한된 운영 반영 → 관찰 → 기록 순서로 진행한다.
- `[x]`는 해당 항목의 완료만 뜻한다. 코드 완료를 배포 완료나 전체 사업 완성으로 바꾸어 쓰지 않는다.
- 테스트 DB는 `kdb_workflow_test`만 사용한다. 운영 DB에 테스트 픽스처를 넣지 않는다.
- 운영 DB 대량 변경·삭제·일괄 병합·보호 정책 해제는 자동 진행하지 않는다.
- 스키마 변경은 백업 복원 검증, 호환성 테스트, dry-run 수량 대조, rollback 방법을 먼저 확보한다.
- 외부 유료 API 도입, 고객 발행 정책 변경, 미해결 인물 병합은 사용자 판단/권한이 필요한 항목으로 분리한다.
- 각 단계에서 실패하면 다음 의존 단계로 넘어가지 않는다. 원인·재현·복구 상태를 기록한다.
- 비밀값을 문서·스크린샷·테스트 로그에 넣지 않는다. 진행은 이 문서로 재개 가능하게 남긴다.

- 오래된 상세 화면/집계에는 현행 90일·입력 변경 정책과 다른 필터가 남을 수 있다.
  새 개요/워크플로우 집계와 기존 목록의 차이를 전수 정렬하는 작업을 후속 UI에 포함한다.
- 현재 이름 기반 재고는 기사 속 동일인 판정이나 요청 언어의 공식 표기 준비가 아니다.
- 기존 K-엔터 게이트를 풀어서 정치/경제/스포츠를 무조건 넣지 않는다.
  분야별 근거·유형·외부 ID·검수 규칙을 먼저 구현한다.
