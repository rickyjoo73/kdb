# 첫 운영 batch 계획 — P2.08 / G2 인수 요청

버전 `first-batch-v1` · 2026-09-13 KST · **승인 요청 문서. 아직 실행하지 않았다.**
근거: [원본 조사](KDB_P2_SOURCE_SURVEY.md) · [검증 한도](KDB_ACCEPTANCE_LIMITS.md) §5 ·
[식별 계약](KDB_IDENTITY_CONTRACT.md) · [P1 기준선](KDB_P1_ISOLATED_BASELINE.md).

> 이 문서가 요청하는 것은 **운영 DB 에 처음으로 쓰기를 하는 승인**이다. P0~P2 전 과정에서
> 운영 DB 는 읽기만 했다. 승인 전에는 아무것도 실행하지 않는다.

## 1. 정확 대상

설계(§5.2)가 정한 파일럿 둘을 실측으로 재확인했다.

### 파일럿 B — TDB 최소 앵커 (먼저 한다)

| 항목 | 값 | 확인 |
|---|---|---|
| 대상 | `tdb_places.place_type='admin_region'` | 249행 전수 |
| QID 보유 | **249 / 249 (100%)** | 실측. 설계 가정과 일치 |
| dry-run `include` | **242** | 구분값 생성 가능·이름 충돌 없음 |
| dry-run `conditional` | **7** | 전부 `동구`·`강동구` — KDB 에 같은 이름이 있다 |
| 1차 batch 에 넣는 것 | **242행** | 보류 7은 동일성 판정 후 별도 |

**왜 여기부터인가.** 249행 전부가 QID 를 갖는 유일한 유형이다(전체 평균은 3.3%). 행정 코드는
공공 표준이라 권리 문제가 없고, 규모가 작아 잘못돼도 되돌리기 쉽다.

### 파일럿 A — KDB 내부 (B 통과 후)

| 항목 | 값 |
|---|---|
| 대상 | active person 의 `person_roles` 채움 (원천 `kwave_entity_person_details`, 운영자 소유) |
| 1차 batch | ≤100 Entity · ≤1,000 변경 객체 |
| 채우는 것 | `person_roles`(verified 는 근거 있을 때만), `classification_status` |
| 제외 | 이름·표기 변경 없음, 병합 없음 |

## 2. 예상 변경 — 정확한 객체 수

파일럿 B 242행이 만드는 것:

| 표 | 행 수 | 내용 |
|---|---|---|
| `kentity_entities` | 242 | 새 UUID + `location`/`admin_region` + **구분값** |
| `kentity_names` | 242 | ko canonical (원천 `name_ko`) |
| `kentity_evidence` | 242 | identity 주장 (원천 `tdb_places` 관측) |
| `kentity_external_ids` | 242 | wikidata QID |
| `kentity_id_reservations` | 242 | QID 단일 소유 (S04) |
| `kentity_crosswalks` | 242 | `(tdb, tdb_places, id)` 연결 |
| `kentity_migration_records` | 249 | 전량 계상 (보류 7 포함) |
| **합계 변경 객체** | **약 1,701** | 한도 ≤1,000 을 넘는다 → **2개 batch 로 쪼갠다** (121행씩) |

> 한도 초과를 자동으로 쪼개지 않는다는 규칙(§5.2 "초과는 자동 쪼개지 않고 계획 검수로")에 따라,
> **여기서 명시적으로 2 batch 로 나눈다.** batch 1: 121행 (약 850 객체), batch 2: 121행.

`kwave_entities`(legacy)는 **건드리지 않는다.** 새 대상은 공통 모델에만 만든다.
소비자 API 는 아직 legacy 를 보므로 서빙에 변화가 없다 — 그게 P5 의 일이다.

## 3. 보호 규칙 선배포 — 쓰기보다 먼저 나가야 하는 것

순서가 뒤집히면 보호 없이 데이터가 들어간다. **반드시 이 순서다.**

| 순서 | 내용 | 왜 먼저인가 |
|---|---|---|
| 1 | `p1_structure.sql` (P1.02, G1 인수분) | 20개 표·복합 FK·EXCLUDE·트리거가 없으면 잘못된 값이 들어간다 |
| 2 | `p2_structure.sql` (완료 guard·단조성·원본 키 인덱스) | 미완성 조사를 완료로 표시하는 것을 막는다 |
| 3 | Go 변경 (P1.02~P1.09 전량) | **1 없이 나가면 운영이 깨진다** — 코드가 새 스키마를 전제한다 |
| 4 | 원천 정책 승인 13 provider | 승인 없는 원천은 읽기 게이트가 막는다(S03). 없으면 아무것도 공급 안 됨 |
| 5 | `kentity_source_guards` 로 의심 연결 751건 차단 | 흡수가 오연결을 승계하지 않게 |
| 6 | **그 다음에야** batch 1 | |

1~3은 한 배포로 묶는다(`deploy.yml` 이 migration→컨테이너 순이라 순서는 맞지만,
`p1_structure.sql`/`p2_structure.sql` 은 `migrations/` 밖이라 **자동 적용되지 않는다** —
P3.02 에서 명시적으로 적용해야 한다).

## 4. 중지 기준 — 하나라도 걸리면 즉시 멈춘다

설계 §5.4 의 수치를 그대로 쓴다. batch 전용으로 셋을 더한다.

| 조건 | 중지 수치 | 출처 |
|---|---|---|
| 5xx (5분 창) | corrections ≥ 1.12%, 그 외 route ≥ 1.0% | §5.4 |
| p95 | lookup/bulk > 566ms · match > 4,015ms · prepare > 3,000ms | §5.4 |
| 저장 | `/data` 여유 < 200GB 또는 백업 1회 실패 | §5.4 |
| 무효화 적체 | outbox 미처리 > 1,000 또는 최고령 > 24h | §5.4 |
| 잠금 | lock wait > 30s 1건 | §5.4 |
| **batch: 계상 불일치** | 기록 수 ≠ 원본 수 **1건이라도** | 신규 |
| **batch: 제약 위반** | 어떤 제약이든 1건 | 신규 |
| **batch: 판정 오류** | 표본 검수에서 오류 1건 | §5.3 |

**"표본 0건을 전체 0으로 표현하지 않는다"**(§5.3)를 유지한다.

## 5. 복구

| 상황 | 복구 |
|---|---|
| batch 중간 실패 | 전체 rollback. 부분 성공을 완료로 보고하지 않는다(I10, P1.06 로 시험됨) |
| batch 후 오류 발견 | `kentity_migration_records.state='reverted'` + 만든 객체 역순 삭제. `run_id` 로 정확히 지목된다 |
| 잘못된 UUID 발급 | 지우지 않고 `status='retired'` + redirect. 소비자가 이미 저장했을 수 있다 |
| 오연결 승계 | `source_guards` 로 차단. 지우면 다음 수집에서 되살아난다 |
| DB 전체 | 일일 백업(2026-09-12 수리 완료, `scripts/kdb-db-backup.sh`) |

**되돌릴 수 있는 이유:** 모든 변경이 한 `run_id` 에 묶이고, 만든 객체마다
`migration_record_id` 로 출처가 남는다(P1.02 §10).

## 6. 승인 책임

설계 §5.5 대로 **운영자 단일**이다. 4개 소비자 사이트·운영·권리의 결정 주체가 같은 사람이며
(P0.06 실측: 동일 호스트·동일 운영자), 외부 담당자 대기 항목은 없다.

판정은 자율 판정기가 하고, 두 판정기가 불일치하거나 근거가 상충할 때만 운영자가 결정한다.

## 8. 승인을 구하는 것 — 정확히 이것

1. `p1_structure.sql` + `p2_structure.sql` 을 **운영 DB 에 적용**한다 (표 60 → 80).
2. Go 변경을 같은 배포로 내보낸다.
3. 원천 정책 13 provider 를 운영에 승인 INSERT 한다.
4. 의심 연결 751건을 `source_guards` 로 차단한다.
5. **파일럿 B batch 1 (121행)** 을 적재하고 계상·표본을 확인한다.
6. 통과하면 batch 2 (121행). 그 다음이 파일럿 A.

**승인하지 않으면 아무것도 실행하지 않는다.** 지금까지처럼 격리에서만 계속한다.
