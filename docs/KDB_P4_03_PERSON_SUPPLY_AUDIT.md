# P4.03~P4.06 선행 감사 — 흡수분 인물의 공급 근거

2026-09-14 · 운영 aiin23 · 전부 실측 (TDB 원본은 읽기만)

P4.02 실측이 다음을 가리켰다: 흡수분의 값어치는 장소가 아니라 **사람**이다.
실수요와 겹치는 흡수분 1,814건 중 1,516건(83.6%)이 인물이고, 흡수분에 인물이
31,377건 있다.

그래서 P4.03 이 요구하는 것을 먼저 확인했다:

> 정치·행정의 인물/기관/정당/직책 원천을 한정 파일럿으로 인수한다.
> **권리·정체성·기간·locale 공급 근거를 확인한다.**

넷 중 **셋이 통과하지 못한다.** 파일럿을 시작하기 전에 이것부터 기록한다.

---

## 1. 집단 — 무엇이 있나

```
흡수분 인물          31,377 (+ subtype 없는 person 4)   전부 status='candidate'
표기(공통 계약 통과, 대상 수)
  ko 31,378 · en 27,231 · ja 19,250 · zh-Hans 15,765 · zh-Hant 14,199
  es 8,227 · fr 5,639 · de 4,074 · id 2,646 · vi 1,193
표기 갈림            0건 (한 대상·한 로케일에 canonical recorded 가 둘 이상인 경우)
```

표기 자체는 좋아 보인다. 예:

```
곽튜브   en KwakTube        zh-Hans 郭俊彬
황재균   en Hwang Jae-gyun  ja 黄載鈞    zh-Hans 黄载均
도겸     en Lee Seok-min    ja ドギョム   zh-Hans 李硕珉
전소연   en Jeon Soyeon     ja ソヨン     zh-Hans 田小娟
```

**KDB 가 존재하는 이유가 이런 것들이다.** 그래서 더 꼼꼼히 봤다.

## 2. ★권리·정체성 근거 — 통과하지 못한다

표기 근거는 이렇게 적혀 있다:

```
provider          wikidata
license_code      CC0-1.0
export_allowed    true
independent_origin wikidata
status            verified
```

그런데 **그 근거가 가리키는 곳이 위키데이터가 아니다.**

```
source_record_id  389e7591-5a5e-4e61-a12d-1031b91a59ad   ← TDB 레코드 UUID
source_url        https://kdb.aiinplanet.com/admin/kentity/76e3a1f9-…  ← 우리 admin
```

`provider='wikidata'` 인 표기 근거 **65,972건 중 65,487건**의 `source_record_id` 가
QID 가 아니라 우리/TDB 의 UUID 다. QID 형태는 **485건뿐**이다.

즉 *"위키데이터가 이 표기를 말했다"* 는 주장은 있는데 **어느 항목인지가 없다.**
CC0 라는 권리 주장도 그 항목이 지목되어야 확인된다. 지금은 확인할 수 없다.

### ★파일럿은 제대로 했다 — 대량 확대에서 떨어뜨렸다

QID 를 제대로 지목한 **485건이 누구 것인지**를 보면 이 결함의 성격이 분명해진다.

```
location.admin_region  484   ← P3 파일럿(p3_batch1 · p3_batch2)
person                   1
대상 수 243 · 그중 verified 외부 ID 로 항목이 지목된 것 243  (100%)
```

`p3_batch1.sql` 은 정체성 근거를 이렇게 썼다:

```sql
provider='wikidata', source_record_id = t.qid,
source_url = 'https://www.wikidata.org/wiki/' || t.qid,
license_code='CC0-1.0', export_allowed=true
```

**항목을 지목하고 그 항목의 주소를 적었다.** 그래서 이 243건은 새 가드를 그대로 통과한다.

반면 대량 확대인 `p3_expand.sql` 은 정체성 근거를 `provider='tdb'` · 자체 URL 로 쓰고,
표기 근거는 `provider='wikidata'` 인데 `source_record_id` 에 **TDB UUID** 를 넣었다.

**계약은 파일럿에서 지켜졌고 규모를 키울 때 떨어졌다.** 53만 건을 다루는 스크립트가
수백 건짜리 파일럿과 다른 근거 형태를 쓴 것이고, 그 차이가 지금 29,169건을 막는다.

### 원본에도 없다

TDB 를 읽어 확인했다(`tdb_places` · `tdb_place_links` · `tdb_place_names`):

| TDB 인물 31,378명 | 수 |
|---|---|
| wikidata 링크 있음 | 14,504 |
| **링크가 아예 없음** | **16,685** |
| 다른 출처 링크만 | 189 |

그러면서 **31,378명 전원이 `source_code='wikidata'` 표기를 갖고 있다.**
링크 없는 사람의 wikidata 표기만 **52,530건**이다(KDB 쪽에서 같은 것을 세면
52,536건 · 대상 16,875명 — 두 DB 가 서로를 확인해 준다).

`tdb_src_records` 에는 wikidata 원본이 보관돼 있지 않다(출처는 aihub_tour ·
ngii_gazetteer · tourapi_* · seoul_dict 뿐). **QID 를 되찾을 곳이 없다.**

이 문제는 거의 인물 전용이다: person 16,874 · heritage 31 · other 1 · work 1.

### ★언제 무슨 일이 있었나 — 날짜가 말해 준다

TDB 의 시각 컬럼을 모아 보면 순서가 드러난다.

| 날짜 | 일어난 일 | 수 |
|---|---|---|
| 2026-08-06 | wikidata 표기 대량 생성 | 61,726 (링크 없는 사람 46,416 · 나중에 링크될 사람 15,310) |
| 2026-08-10 | 추가 생성 | 9,300 |
| **2026-08-15** | **wikidata 링크 생성 — 전부 이 하루** | **14,504** |
| 2026-08-18 | 링크된 항목에서 라벨 읽음(`labels_read_at`) | 14,276명 · 표기 56,446 |

즉 **`source_code='wikidata'` 표기 73,320건이 링크가 생기기 전에 만들어졌다.**
여기엔 인물 전원의 ko 31,378 · en 12,995 · ja 11,126 · zh-Hans 8,532 · zh-Hant 8,162 이
들어 있다. 링크가 없던 시점의 표기이므로 **어떤 항목에서 왔다고 말할 수 없다.**

표기 `verified_at` 과 `labels_read_at` 을 맞대면(링크 있는 사람의 wikidata 표기 75,061건):

```
같은 시기(±1일)  56,445
표기가 더 이름   18,609   ← 링크보다 먼저 있던 표기
표기가 더 늦음        7
```

`황재균` 이 그대로 보여 준다 — 링크 `Q11287837` 은 08-15, 라벨 읽기는 08-18,
그런데 `ko 황재균` 의 `verified_at` 은 **08-06** 이다.

**그래서 항목 식별을 회수할 수 있는 것은 08-18 묶음뿐이다**(약 14,276명 · 표기 56,446).
나머지는 회수가 아니라 **새 관측**이어야 한다.

### 링크가 있는 14,504명조차 근거로 옮겨지지 않았다

`황재균` 은 TDB 에 `wikidata Q11287837 method=kowiki+en-fp score=0.900` 이 있다.
그런데 KDB 의 표기 근거 `source_record_id` 는 여전히 TDB UUID 다.
**흡수가 항목 식별을 근거로 옮기지 않았다.** 링크는 `kentity_external_ids` 에
`status='unverified'` 로만 남았다(14,502건, 전부 예약됨 / verified 는 1건).

## 3. 분야 근거 — 없다

P4.03~P4.06 은 정치·경제·스포츠·연예로 나눠 파일럿을 하라고 한다. 그런데

```
흡수분 인물의 분야 배정:  (없음) 31,377 · sports 2 · economy 1 · politics 1
```

**31,377명 전원이 분야 미배정이다.** 나눌 근거가 원장에 없다.

TDB 에도 없다. `tdb_places` 의 person 행은 이렇다:

```
disambiguator  0건 채움
notes          0건 채움
source_urls    0건 채움
prominence     31,378건 전부 동일값 20
```

**이름과 `place_type='person'` 말고는 아무것도 없다.** 직업 근거
(`claim_type='occupation'`)는 원장 전체에 204건이고 **전부 기존 원장(kdb) 소유**다.

분야를 알아내는 길은 QID 를 통한 위키데이터 조회뿐인데, 그것은 16,685명에겐
아예 불가능하고 나머지에겐 새 수집 작업이다.

## 4. 기간 근거 — 없다

P4.03 은 "기간"(재임·활동 기간)을 확인하라고 한다. TDB 인물 레코드에 기간 필드가
없고, 흡수분에도 없다. 정치인의 직책 기간을 말할 근거가 **0건**이다.

## 5. locale 공급 근거 — 이것만 통과한다

표기는 recorded 이고, 갈림이 0건이고, 승인된 정책(`wikidata`, CC0-1.0,
`name_export_allowed=true`)이 있다. **넷 중 통과하는 것은 이 하나뿐이고, 그마저
§2 때문에 "어느 항목의 라벨인지"를 말하지 못한다.**

## 6. 정체성 충돌도 있다

| 검사 | 수 |
|---|---|
| 같은 ko 이름의 **활성** 기존 원장 대상이 있음 | 3,607 |
| 같은 ko 이름의 기존 원장 대상이 있음(상태 무관) | 3,976 |
| 흡수분 안에서 같은 ko 이름 | 534 |
| **QID 가 기존 원장(`kwave_entity_external_refs`)에서 이미 쓰이는 중** | **1,778** |

마지막 줄이 특히 중요하다 — 그 1,778명은 기존 원장 대상과 **같은 위키데이터 항목**이다.
"한 대상 = 하나의 ID"(I01)에 정면으로 걸리므로 별도 활성화 대상이 아니라
**동일성 판정(P5)의 대상**이다.

표본에서 `하나`(person)가 신보라의 표기(en `Shin Bo-ra` · ja `シン・ボラ` ·
zh `辛衍抒`)를 ko `하나` 아래 달고 있는 것도 확인했다.

## 7. 그래서 한 일 — 활성화 도구에 가드를 넣었다

P4.02 에서 만든 [`activate_absorbed_supply.sql`](p4/activate_absorbed_supply.sql) 은
**이 결함 대상들을 그대로 열어 줬다.** 실측: 가드 없이 활성화 가능한 대상 **15,009건**
(인물 14,982 · location 26 · work 1).

각 조각은 옳은데 이어 붙이면 틀리는 자리다 — 그 스크립트는 여행 대상을 기준으로 썼고,
여행 표기의 출처(`tourapi_*`·`aihub_tour`·`seoul_dict`·`ngii_gazetteer`)는 **데이터셋
단위로 권리가 정해지는 벌크 출처**라 항목 식별이 권리의 근거가 아니다. 위키데이터는
**항목 단위**다. 같은 규칙이 두 출처에 다르게 적용돼야 했다.

추가한 가드:

> 공급할 표기의 근거가 **항목을 가진 출처**를 말하면, 그 항목이 지목돼 있어야 한다.
> 대상에 그 출처의 `verified` 외부 ID 가 있고, 근거의 `source_record_id` 가 그것과
> 같아야 한다.

항목을 가진 출처를 손으로 적지 않는다 — **`kentity_external_ids` 가 정체성을 정의하는
출처가 곧 그것**이다(현재 데이터에선 `wikidata` 하나, 17,914건). 출처가 늘면 규칙이
저절로 따라간다.

**효과 실측**

```
가드 전 활성화 가능(동명 함정 제외 뒤)   365,790
가드가 막는 수                            29,169
  └ person 27,692 · location 1,438 · work 31 · event 8
```

막히는 것이 인물만은 아니다 — location 1,438건도 위키데이터 표기에 기대면서 항목을
지목하지 못한다. 규칙을 `person` 으로 좁게 쓰지 않고 **출처의 성격**으로 쓴 이유다.

가드 시험(격리 아님, dry=1 운영 대조):

```
백이슬       인물, QID 없음        → 막힘
신승리       인물, QID 있으나 근거에 미지목 → 막힘
선국사대웅전 유적, 벌크 출처 표기   → 통과
```

P4.02 에서 실제로 연 `서울패션위크`도 새 가드를 **통과한다** — 공급 중인 두 표기가
`seoul_dict`(공공누리 제1유형, 데이터셋 단위 권리)이기 때문이다. 앞선 판단이 유지된다.

**지금 활성 상태로 이 결함 근거에 기대고 있는 대상: 0건.** 예방 조치다.

## 8. 파일럿을 하려면 무엇이 필요한가

P4.03~P4.06 을 지금 시작할 수 없다. 필요한 것을 순서대로 적는다.

1. **항목 식별 회수 — 08-18 묶음에 한해서.** TDB 가 실제로 그 항목에서 라벨을 읽은
   표기(약 14,276명 · 56,446건)에만 QID 를 근거로 옮기고 `kentity_external_ids` 를
   `verified` 로 올린다. **링크보다 먼저 있던 표기 18,609건은 회수 대상이 아니다** —
   그 항목에서 왔다는 증거가 없다. §6 의 1,778건(기존 원장이 이미 쓰는 QID)도
   **제외**하고 P5 로 보낸다.
2. **분야 판정 근거 확보** — 1 이 끝나야 QID 로 직업/분야를 물을 수 있다.
   이것이 실제 "원천 인수"이고, P4.03~P4.06 의 본체다.
3. **QID 가 없는 16,685명** — 위키데이터 출처 주장을 유지할 근거가 없다.
   근거를 사실대로 내리거나(provider/license 정정), 다시 관측하거나, 둘 중 하나다.
   **지어내지 않는다**(D-37). 이건 별도 결정이다.
4. **기간** — 정치 직책의 기간은 이 집단에 근거가 없다. 다른 원천이 필요하다.

1~3 은 각각 운영 데이터 수만 행을 바꾸는 일이라 별도 게이트로 다룬다.
이 문서는 **무엇이 왜 막혀 있는지**까지만 확정한다.
