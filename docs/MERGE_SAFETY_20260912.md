# 동명이인 병합 안전성 보강 — 2026-09-12

## 적용 상태

작업본 구현. 운영 미반영. 운영 버전은 `kdb-app:workflow-20260912-3` 그대로다.
전체 TODO나 공통 Entity 통합 완료 보고가 아니다. 스키마 migration은 없다.

## 확인된 문제와 변경

- 기존 근거 이관, 별칭 추가, variant 비활성화, 인물 상세 이동은 별도 SQL이었다.
  오류를 무시해 부분 저장 후에도 merged로 보고할 수 있었다.
- 승자/패자 UUID 순서로 행 잠금 → 상태/운영자 잠금 확인 → 모델 입력 스냅샷 대조 →
  근거 충돌 검사 → 근거/표기/별칭 승계와 비활성화 → commit을 한 트랜잭션으로 묶었다.
- SERIALIZABLE, lock_timeout 2초, statement_timeout 10초, 전체 15초 상한.
  실패·취소 시 rollback. 직렬화 실패는 완료로 보고하거나 맹목적으로 재시도하지 않는다.
- 현재 값과 입력 hash뿐 아니라 생년과 모든 외부 ID도 비교한다.
  기존 fill_input_hash는 생년 변경을 포함하지 않아 hash 단독 검사로는 부족하다.
- 자동 병합은 active 승자, 같은 알려진 유형, 같은 유효 Wikidata QID, 충돌 없는 근거가 필요하다.
  같은 이름/직업/소속/생년은 단독 식별자가 아니다. 다른 provider는 식별자 namespace 정책을
  검증한 뒤 별도로 허용한다. 보수적으로 검수량이 늘어날 수 있다.
- 모델 응답의 중복 ID, 군집 밖 ID, 자기 병합, 병합 연쇄/순환,
  명시적으로 남길 대상이 없는 병합은 쓰기 전에 거부한다.
- 승자 label 변경은 해당 군집의 병합 뒤에 실행한다. 자체 metadata 변경이
  입력 hash를 바꿔 정상 병합을 불필요하게 거부하지 않도록 한다.
- 비활성화 메모에 승자 UUID를 남긴다. 물리 삭제하지 않으며 실제 commit 후에만 merged로 보고한다.
- 격리 메모 동일 사유 반복 추가 방지, 잠김/기각 대상 쓰기 거부, 실패 시 errored 보고.
- 수동 과거 근거 복구 CLI 경로도 같은 트랜잭션·잠금·안정 ID 게이트를 사용한다.
  별칭 일치만으로 복구 대상을 확정하지 않는다. 이번에 해당 CLI를 실행하지 않았다.

## 검증

테스트는 전용 `kdb_workflow_test`의 무작위 격리 schema에서만 실행한다.
운영 데이터에 테스트 인물을 넣지 않는다.

`internal/kdb/agents/disambiguator/merge_integration_test.go`의 12개 테스트 함수:

1. 근거/표기/출처/등급/상세와 비활성화의 정상 commit, 중복 요청 방지.
2. 후반 비활성화 실패 시 먼저 복사한 근거/표기/별칭 전체 rollback.
3. 승자/패자 잠금, 모델 판단 이후 생년/QID/유형 변경 거부.
4. 같은 이름·직업·생년만으로 자동 병합하지 않음.
5. QID가 같아도 다른 provider의 식별자가 충돌하면 보류.
6. A→B와 B→A 동시 실행에도 하나의 live Entity만 남음.
7. 행 잠금 대기 취소 후 부분 저장/잔여 잠금 없음.
8. 중복/순환/연쇄/군집 밖 모델 명령의 부분 실행 방지.
9. 반복 격리 메모 멱등성, 기각 대상 보호, 저장 오류 보고.
10. 모델이 승자 결정을 먼저 반환해도 자체 label 변경 전 병합.
11. 과거 근거 복구 시 같은 안정 ID를 요구함.
12. 서빙 중인 active Entity를 미승격 candidate에 병합하여 사라지게 하지 않음.

최종 검증 통과: `KDB_SKIP_LIVE=1 go test ./... -count=1`, `go build ./...`,
disambiguator/enricher/autopilot/admin의 `go test -race ... -count=1`, `git diff --check`.
실시간 외부 소스 테스트 및 운영 트리거 검증/배포 완료를 의미하지 않는다.

## 배포 전 남은 검증과 경계

- 운영 스키마/제약/실제 hash 트리거를 복원 환경에서 검증하고 최신 백업 게이트를 통과해야 한다.
- 운영 소스는 이미 1차 수정으로 dirty 상태다. 현재 운영 파일 기준으로 충돌 대조 후 patch한다.
  이전 1회용 promotion 도구를 그대로 실행하지 않는다.
- 정규 작업의 반복 격리 원인은 아직 완전히 해결한 것이 아니다. Select/Run 군집 차이,
  중첩 군집, 파트너 없는 항목의 재선정, 입력 변경에 따른 재개 정책은 별도 검증한다.
- 여러 variant가 한 승자에 연결될 때 앞선 commit으로 스냅샷이 달라지면 뒤 작업은 보류한다.
  안전성을 위해 다시 판단하며 한 군집 전체를 무조건 일괄 병합하지 않는다.
- 구조화된 merge audit/redirect, 관계·요청·mention의 UUID 연결, 운영자 비교/승인 UI,
  기존 persons 이름 UNIQUE 교정은 공통 Entity 단계에 남아 있다.
- 요청 언어별 준비 원장, 분야별 공식 source adapter, TDB 이관은 이 변경에 포함되지 않았다.
- Go 동시성 race 테스트가 모든 실제 DB writer와 운영 작업의 동시 실행을 보장하지는 않는다.
