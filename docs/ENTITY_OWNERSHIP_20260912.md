# 기존 용도 제한과 공통 Entity 쓰기 책임 전환

2026-09-12. migration 0118. 배포/검증 결과는 운영 인수인계 문서가 기준이다.

## 발견한 실제 정책 충돌

대한적십자사 `7478b5bf-15c7-4fb8-a6b7-6be9eb2d5b8e`는 기존 KDB에 존재한다.
구형 기각 기록은 일반 사회·구호 기관이며 K-엔터테인먼트 범위 밖이라는 이유였다.
따라서 신규 UUID를 만들어 회피하거나 모든 기각 레코드를 활성화하면 안 된다.
[기관의 공개 소개](https://www.redcross.or.kr/main/cm/conts/contsView.do?contsId=1062&mi=2428)는
공통 사회 분야에서 다시 조사할 근거이며, 외국어 공식 표기나 재사용 권한의 일괄 승인이 아니다.

## 결정

- `origin_system`은 최초 출처로 불변, `write_owner`는 현재 쓰기 책임으로 분리한다.
- 기존 KDB UUID/고정 언어값/기각 기록/잠금은 보존한다. 기본은 계속 KDB writer다.
- 운영자가 사유·HTTPS 근거·유형·분야를 확인한 **기각·미잠금 단일 UUID**만 전환한다.
- 변경은 SERIALIZABLE, legacy parent→common root 순서 잠금, revision+원본 fingerprint 재검사다.
  판단/감사/새 조사 job은 한 트랜잭션이다. 실패하면 전체 취소된다.
- 공통 상태는 candidate, 이름은 한국어 미검증 하나부터 시작한다. 구형 외국어 값을 승인·복사하지 않는다.
- 기존 연예 분야 추정은 선택한 새 분야로 교체하고, 이전 분야/유형도 감사 전후 값에 보존한다.
- 같은 UUID는 유지하며 이후 기존 자동화의 타입·이름·기각 상태가 공통 값을 덮어쓰지 않는다.
  기존 KDB API가 공통 승인 이름을 제공하게 되는 것은 아니다. 소비자 전환은 별도다.
- 본인의 기존 외부 ID는 충돌로 오인하지 않는다. 다른 UUID의 외부 ID 충돌/예약 보호는 유지한다.
- 공통 증거 철회 시 최초 출처가 KDB여도 표기·식별자·활성 상태를 차단한다.

## 보호 잠금과 운영 화면

`/admin/kentity/{id}`에서 원래 출처와 현재 쓰기 책임을 따로 표시한다.
기각된 기존 기록은 기각 사유와 범위 전환 폼을 제공한다. 전환 후에는 공통 조사/검수/잠금 경로다.
조회자에게 변경 폼을 노출하지 않고 POST는 DB 권한 재확인, CSRF와 16 KiB 제한을 적용한다.

공통 잠금 변경은 사유/현재 revision/감사 이벤트를 요구한다. 기존 KDB 잠금은 공통에도 전파되지만,
구형 잠금을 해제해도 공통 잠금은 자동 해제하지 않는다. 공통 해제는 구형 잠금이 남아 있으면 거부된다.
잠금 변경은 revision을 증가시켜 이전 조사 결과의 저장·승인을 차단한다. 해제 후 현재 버전으로 새
조사를 요청할 수 있다. 이전 조사 결과는 버전 경고와 함께 보존하며 자동 승인하지 않는다.
