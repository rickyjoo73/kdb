# KDB 요청 가이드 — 소비자(kstory·trendbiz·issuetalk)용

KDB가 키워드를 **빠르고 정확하게** 해소하려면 요청 품질이 절반입니다.
아래 기준을 지키면 처리 속도와 정확도가 크게 올라갑니다 (2026-07-16 제정).

## 1. 무엇을 보내야 하나 (필드별 기준)

### `query` / `keyword` — 키워드 (필수)
- **고유명사 원형 그대로, 1개만.** 기사에 나온 표기 그대로 보냅니다.
  - 좋음: `아이유`, `폭싹 속았수다`, `방탄소년단`
  - 나쁨: `아이유 콘서트 티켓`(조합어), `아이유/IU`(병기), `배우 아이유`(수식어),
    `K-POP`(일반 장르어 — 고유명사 아님), 오탈자
- 일반명사·장르어·행사 카테고리(콘서트, 팬미팅, 컴백)는 보내지 마세요. 게이트에서
  기각되며, 반복 시 요청 노이즈만 쌓입니다.

### `type` — 유형 힌트 (권장, 정확할 때만)
- `person / group / drama / movie / show / song_album / event_tour / agency / brand_place / character`
- **확실할 때만 지정하세요. 모르면 `unknown`으로 보내는 것이 잘못된 타입보다 훨씬 낫습니다.**
  잘못된 타입은 오분류를 만들고 해소를 늦춥니다(실측: 가수를 song_album 으로 보낸 요청이
  가수 엔티티를 곡으로 오염). 기사 문맥이 "배우 ○○○"라고 말할 때만 person, 확신 없으면 unknown.

### `context_hint` — 기사 문맥 (강력 권장)
- 키워드가 등장한 **기사 문장 1개** (최대 200자에서 절단됨). 동명이인·동명작품 구분의
  핵심 재료입니다.
  - 좋음: `배우 박정훈이 드라마 '무영'에 캐스팅됐다`
  - 나쁨: 기사 전체 본문, 키워드 반복, 빈 값
- context 없는 동명 키워드(김민수, 박정훈…)는 보류될 확률이 높습니다.

### `source_url` — 기사 URL (강력 권장)
- 근거 재수집·자동검증이 이 URL을 신뢰 판단에 씁니다. 신뢰 매체 URL이면 게이트 통과가
  빨라집니다.

### `origin` — 요청 성격 (필수로 정착시킬 것)
- `lookup-miss`(지금 번역에 필요) 또는 `prepare`(곧 쓸 키워드 사전 준비)를 명시.
- KDB는 lookup-miss 를 우선 처리합니다. origin 없는 요청은 우선순위를 받지 못합니다.

## 2. 응답을 읽는 법

- miss 응답 = `preparing`: KDB가 즉시 발굴 중(평균 15초). 잠시 후 재조회하세요.
- `status=rejected` 로 조회되는 키워드 = 의도적 기각(일반어·비K·오염). 재요청하지 마세요.
  이의가 있으면 교정요청(/v1/corrections)으로.
- 번역힌트 신뢰 기준: `operator_locked=true` 또는 `confidence>=0.9` 만 자동 채택 권장.
- `provenance=machine-translation` 값은 기계번역 폴백입니다. 공식 표기가 확보되면 자동
  교체되므로, 캐시를 오래 들고 있지 말고 주기 재조회하세요.

## 3. 하지 말 것

- 같은 키워드 반복 요청(수 분 내) — 중복 종결만 쌓입니다. preparing 후 재조회가 정답.
- 목록 통째 던지기(기사에서 추출한 모든 명사) — 게이트 보류가 쌓여 정작 필요한
  키워드 처리가 늦어집니다. **기사당 실제 번역에 필요한 고유명사만.**
- 타입 추측해서 채우기 — 모르면 unknown (§1 type).
