# KDB 오염 재감사 — Gemma 다회투표 + gpt-5.5 에스컬레이션 (2026-06-21)

상태: **설계 (검증 일부 완료, 구현 전)**

## 목적
active 엔티티의 **canonical_ko 오염**(일반어·문장조각·깨진문자열·비실체)과 **범위밖**(실재하나 비-K:
운동선수·외국밴드·지명)을 찾아 정리. 오염된 한국어가 다국어로 번지는 것을 뿌리부터 차단.

## 핵심 교훈 (6라운드 검증)
- Gemma 단독 판정은 **신인·무명을 오염 오판**(코르티스/CORTIS) → 검색 veto 필수.
- 검색 veto는 **K-범위 인식**이어야(박인비 골프선수가 "실재"로 잘못 구제됨).
- 경계 케이스(버라이어티·Lights·고음불가)는 **매 실행 판정이 뒤집힘**(검색변동+LLM경계). 변수 0 수렴 불가.
- **temp=0 다회투표는 무의미**(결정론). **temp=0.8 필수** → 경계는 표 갈림, 명백은 만장일치.

## 구조 (4계층 게이트 — 경계는 절대 자동삭제 X)
```
1. SQL 1차 필터 (싼 의심 추림)
   한글누출·한국어복사(351건)·짧은 일반어형·게이트키퍼 노트 등 → 후보군
2. Gemma 다회투표 (서버22, temp=0.8, N=5)
   S1 4분류(real_k/contaminated/out_of_scope/uncertain) + 검색 veto(K-범위 인식 S2)
   ├ 만장일치(또는 ≥4/5) → 그 verdict 고신뢰 확정
   └ 표 갈림 → uncertain → ③ 에스컬레이션
3. gpt-5.5(Codex) 에스컬레이션 (경계 건만 — 비용절감)
   엔티티 + 검색결과 + Gemma 표분포 제공 → 최종 판정
   └ gpt-5.5도 불확실 → ④
4. 운영자 검토 플래그 (자동삭제 X)
```

## 행동
- **contaminated 확정** → `status='rejected'` + 감사로그 → 다국어 값도 함께 무효(번짐 제거).
- **out_of_scope 확정** → 범위밖 플래그(운영자 검토; 자동삭제 X).
- **real_k** → 유지.
- 모든 자동 reject는 `kwave_kdb_dataqa_log` 류 감사로그 → 되돌리기 가능.

## 검증 실측 (2026-06-21)
- 검색 veto: 코르티스·수목금·고음불가·유어즈·어쩔수가없다·모둡 정확 구제(실재 신인/무명).
- 3분류: 박인비(골프)·키린지(일본밴드)·레드우드시티(지명) 범위밖 정확.
- 명백 오염: 세계일주·데뷔·초연나건소사·건강하게 확정.
- 다회투표 temp=0.8: 박인비·Lights·세계일주(경계)=표갈림→에스컬, 코르티스(명백)=만장일치.

## 안전 원칙
- 검색 veto = 신인 오삭제 방지. 다회투표+gpt5.5+운영자 = **경계 3중 게이트**.
- 서버22에서 검색(22 IP는 Google 덜 막힘, 단 **DDG·소량·throttle** — Google News는 대량시 503).
- Gemma 로컬:8080(키 불필요), 에스컬만 gpt-5.5(Codex, 고비용이라 경계만).

## 구현 (서버22 워커 + KDB)
- 서버22: 다회투표 감사 스크립트(Gemma 로컬 + DDG) — 후보군을 배치·throttle 처리, 표분포 산출.
- KDB: 에스컬레이션 = 기존 `aijudge`(provider=codex / `KDB_LLM_<role>=codex`). reject/플래그·감사로그 기록.
- 게이트: `KDB_CONTAM_AUDIT_ENABLED`, 배치크기·throttle·일일한도.

## 누락(gap) 보강과의 관계 — 동전의 양면
- 오염=틀린데이터 reject / 누락=빈 locale·메타 채움. 같은 Gemma+검색+구조화DB.
- 누락 채움 우선순위: TMDb(translations+alt_titles) > Wikidata(label/alias/sitelink) > MusicBrainz > Gemma검색(서버22).
- 오염 reject 후 정상 엔티티는 누락 보강 파이프라인으로.
