## 1. gemma 를 쓰는 이유와 한계 인정

- 이유: 자체 함대(3대×2슬롯) = **무료·무제한·무외부의존**. 판단이 필요한 지점에 비용 걱정
  없이 투입 가능(네이버 쿼터 1,000/일, 구글번역 과금과 대비).
- 한계: 26B 급 — 지시가 모호하면 규칙을 과적용/과소적용한다(실측: "문장형=쓰레기" 규칙을
  실제 문장형 제목에 과적용 → 오거부 사고 07-17). **성능 한계는 프롬프트+권한설계+측정으로
  보정한다. 보정 불가하면 그 판단 지점에 gemma 를 쓰지 않는다.**

## 2. 판단 지점 지도 — 어디에 쓰고, 어디에 안 쓰는가

| 판단 지점 | 주체 | gemma 권한 | 이유 |
|---|---|---|---|
| 게이트 통과/보류/기각 | 규칙(DecideIntake) | 증거 수집만 | 결정론·감사 가능해야 함 |
| 오염 키워드 기각(triage) | gemma | 기각만(승격 불가)·복원 가능 | 회색지대, 오판 피해 한방향 |
| 타입 재판정(type-retrace) | gemma | 교정 제안→스냅샷 후 적용 | 공식소스 도착 시 자동 대체됨 |
| 실재성 승급(evidence) | gemma | unverified→evidenced 만 | authoritative 는 공식소스 전용 |
| 번역용 맥락문장 | gemma | 문장 생성(철자보존 검증 통과 시만) | 실패 시 템플릿 폴백 |
| **서빙 값 확정** | **소스 우선순위 규칙** | 없음 | LLM 값=최하위, 공식소스가 밀어냄 |
| **동명이인 분리(critical)** | codex(고성능)·메시 | 없음 | 품질 critical 은 상위 모델 |

## 3. 가이드(프롬프트) 작성 5원칙 — 전 프롬프트 준수

1. **JSON 스키마 강제** — 형식 이탈은 파싱 실패=무동작(오염 없음).
2. **판단 범위 최소화** — 한 프롬프트 한 질문. "판정"만 시키고 결정·집행은 코드가.
3. **보수 기본값 명문화** — "모호하면 후보 유지", "실재 이름 기각이 최악의 오류" 를 문장으로.
4. **실사례 예시 필수** — 도메인 특성(한국 제목은 문장형이 흔함: '죽어도 좋아', '이번 생은
   처음이라')을 예시로 박는다. 규칙만 쓰면 과적용된다(07-17 사고의 원인).
5. **1k 토큰 이내** — gemma 실측 최적 구간. 입력에 없는 사실 생성 금지 조항 필수(환각 방지).

## 4. 품질 게이트 — 프롬프트는 측정 없이 배포 금지

- **골든셋 평가**: `kdb-app triage-eval` — 실사고 사례 포함 20케이스(실제 제목 10 + 쓰레기 10).
  **통과 기준: 오거부 0건(절대) · 쓰레기 놓침 ≤2건.** 프롬프트 변경 시 실행 필수, FAIL 이면 배포 금지.
- 실측 기록: 2026-07-17 v2 프롬프트 **PASS** (오거부 0, 놓침 1 — "오늘의 운세"는 방송 코너명
  가능성이 있어 보수 판정이 오히려 방어적).
- 골든셋은 새 오판 사례가 나올 때마다 추가한다(회귀 방지).

## 5. 책임 체계 — "만들고 방치" 를 구조적으로 불가능하게

1. **모든 자동 결정은 복원 가능**: 엔티티 기각/교정=dataqa_log 스냅샷(revert 명령 존재),
   큐 기각=발굴 큐 승인 버튼. 07-17 오거부 사고 때 24+176건을 3분 내 전량 복원한 것이 실증.
2. **모든 gemma 출력은 로그**: 판정+사유 전수 기록 → 표본 감사 가능(사고 발견 경로였음).
3. **사후 감사 루프**: TypeVerifier(매일 05:30)·EvidenceVerifier·dataqa 가 승인 후 오염을
   상시 재검증. gemma 1차 판단의 오류를 잡는 2차 방어선.
4. **수렴 보장(TTL)**: 어떤 키워드도 무한 보류 없음 — 근거 없음 21일이면 자동 종결(복원 가능).
5. **실적 노출**: /admin/agents 에 에이전트별 라이브 실적 — 숫자가 멈추면 죽은 것이 보인다.
