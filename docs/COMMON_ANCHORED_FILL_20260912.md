# 공통 Entity의 요청 언어 자동 보충

상태: 0121 개발·배포 검증 중. 운영 반영 여부는 최신 운영 인계 문서를 우선한다.

## 범위와 준비의 의미

이미 검수된 정체성에 **빈 요청 언어**를 추가한다. 신규 동명이인 정체성을 자동 승인하는 기능은 아니다.
기존 `kentity_locale_fill_jobs`를 공유하며 정책 `common-anchored-fill-v1`로 레거시 작업과 분리한다.
Go API는 DB에 수요와 작업만 등록한다. 네트워크 원천 조회는 별도 worker에서 실행한다.

자동 보충의 조건:

- 명시된 UUID와 한국어 이름/검수된 별칭·유형이 일치하는 공통 요청.
- native writer / active / 잠금 없음 / 재사용 가능한 검증된 정체성 근거.
- 정확히 하나의 검증된 Wikidata QID와 그 ID의 독점 예약. 타 legacy UUID의 주장이 없어야 한다.
- 해당 QID의 HTTPS 원천, CC0 구조화 데이터, 검증/관측 시각과 검수 기록.
- 대상 locale에 **어떤 기존 이름 행도 없어야 한다**. 미검증/생성/만료/철회 행도 덮어쓰지 않는다.
- 새 조회의 QID·한국어 이름/별칭·인물 여부가 기존 검수와 일치해야 한다.
- 정확한 원문 locale와 문자 검사를 통과해야 한다. `pt`를 `pt-BR`, `zh`를 `zh-Hans`로 바꾸지 않는다.

저장 상태 verified는 원문 기록의 **정해진 정책 검사 통과**라는 의미다. 사람이 그 언어를
검수했거나 공식 명칭으로 인증했다는 주장이 아니다. `verified_by=policy:common-anchored-fill-v1`,
감사 이력의 `human_locale_review=false`/`official_name_asserted=false`로 구분한다.
외부 응답에는 운영자 이메일 대신 `verification_method`를 노출한다.
공통 이름 목록/요청 상세에 자동 확인과 운영자 검수를 구분하고 근거 링크/버전을 제공한다.

## 트랜잭션과 원천 철회

요청 → 작업 → Entity/근거/외부 ID/이름 순으로 잠그고 SERIALIZABLE 트랜잭션에서 저장한다.
진행 중인 요청 취소, lease 만료/교체, 정체성·근거·잠금 변경, 기존 이름 추가 시 결과를 버린다.
다른 언어의 보충은 대상 언어의 재시도 예산이나 기존 준비 시각을 초기화하지 않는다.
원천 에러는 1/2/4분 backoff, 원천 부재는 7일 간격, 자동 조회는 같은 입력에서 최대 4회다.
운영자 재확인은 기존처럼 5분 간격·작업당 24시간 창 3회·회당 최대 4번 제한과 감사 기록을 유지한다.

0121 `kentity_evidence_dependencies`는 자동 이름의 근거와 검수된 정체성 근거를 연결한다.
정체성 근거가 철회되거나 재사용 권한을 잃으면 이에 의존한 이름 근거와 이름도 차단한다.
다른 정체성 근거 때문에 Entity 자체가 active로 남아도 철회된 근거의 자동 이름은 사용할 수 없다.
관계는 같은 Entity의 name→identity로 제한한다. 준비 조회는 현재 DB 상태를 다시 검사한다.

## UI / 호환성 / 운영 게이트

- 준비 상세는 실제 보충 작업이 있는 실패/원천 부재 언어에만 공통 재시도 버튼을 표시한다.
- 기존 요청의 policy/API 의미를 바꾸지 않고 새 보충 정책의 작업을 분리한다.
- `KDB_COMMON_FILL_ENABLED=1`, common Entity/readiness gate가 모두 필요하다.
- 신규 gate를 꺼도 이미 저장된 정상 기록의 조회는 가능하다. 저장된 이름을 철회하려면
  근거 status/export_allowed를 명시적으로 철회해야 한다. 단순 gate off는 데이터 삭제가 아니다.
- 문제 시 gate를 끄고 writer-aware 이전 앱으로 복귀한다. DB/감사 이력은 보존한다.

Wikidata 클라이언트는 zh-hans 원문 label도 요청하지만 레거시 zh 접기 규칙은 바꾸지 않는다.
추가 UI 점검에서 발견한 정치 필터의 잘못된 option 태그를 수정하고 행정/문화 필터도 보완했다.

## 통과해야 할 검증

격리 DB: 정확 locale, 다른 언어 처리 시 예산 유지, 중복, 취소/잠금/기존 이름/ID·유형 불일치,
근거 철회, 다른 정체성 근거가 남을 때의 종속 이름 차단, gate/tenant/수동 재시도 한도,
마지막 lease 만료, HTTP 생성→worker→조회, UI의 검수 방식/근거/재시도 표시.
전체 Go test/build, 관련 race, 최신 운영 백업 복원, 390px/1440px 브라우저 및 정상 운영 로그인.

신규 후보의 완전 자동 정체성 승인, TDB 실제 crosswalk/소비자 전환, 분야별 공식 원천,
기사 NER·Glossary·번역/발행과 전체 관리자 인수는 별도 남은 작업이다.
