# 고유명사 운영센터 — UI 우선 수직 구현

요청: 첫 화면에서 신규 등록과 분야별 활용 현황을 확인할 수 있어야 한다.
UI 모형만 배포하지 않고 실제 DB 집계·필터·상세·기존 검수 기능까지 연결한다.

## 이번 인수 범위

- [ ] 첫 화면에 공통 고유명사 운영센터, 분야 카드, 신규 등록 목록과 작업 진입점 제공.
- [ ] 공통 목록에 유형·분야·상태·원출처 필터, 등록/정체성 변경순 정렬, 페이지 탐색 제공.
- [ ] 등록 폼을 직접 여는 링크와 상품·개념·미확인 유형까지 제공.
- [ ] 미분류 수량/목록을 명시한다. 기존 KDB 출처만으로 연예 분야를 추정해 일괄 분류하지 않는다.
- [ ] 등록 시각과 정체성 변경 시각을 구분한다. 레거시 표기 변경 전체 이력으로 과장하지 않는다.
- [ ] 실제 SQL 집계/필터·오류·권한 회귀·모바일/PC·운영 로그인 검증 후 배포한다.

## 화면 계약

`/admin/` → 운영센터 검색 / 등록 진입 / 신규 24h / 미검증 후보 / 분야 미지정 /
8개 분야 카드 / 최근 등록 8건 / 기존 상세 운영 지표.

`/admin/kentity` → 전체 집계 / 조합 필터 / 등록·정체성 변경 시각 / 50개 페이지 /
`?create=1#candidate-create` 등록 폼. 등록 후 기존 동일 UUID 상세와 자동 조사로 이동한다.

모든 카드 수는 공통 Entity 원장 기준이며 승인된 언어 수나 전체 수집 목표 달성률이 아니다.
다중 분야는 중복 집계될 수 있다. 분야 0건은 삭제가 아니라 분류 연결 부재일 수 있다.
신규 24h는 원장에 보존된 created_at 기준이며 이관한 날을 신규로 부풀리지 않는다.
공통 기능 비활성 시 기존 대시보드 유지. 조회 실패를 0으로 표시하지 않는다.

## 후속 (이번 배포 완료와 구분)

기존 데이터 분야 분류와 근거·검수 경로, 공식 정치/경제/스포츠 출처 adapter,
누락 자동 발견 및 실제 요청별 보충 효과, Gemma 작업별 비용/수율, TDB 원본 교정/이관,
기사 문맥 linking/Glossary/PressLocale/CMS 종단 간 연동은 별도 완료 게이트가 필요하다.
시간 예상: 본 UI/실데이터 연결 1~2시간의 초기 추정. 분야별 데이터 품질 작업은 수일 이상이며
외부 출처·권리·실측 검증에 따라 달라진다. 전체 플랫폼 완료 시각을 약속하는 문서가 아니다.
