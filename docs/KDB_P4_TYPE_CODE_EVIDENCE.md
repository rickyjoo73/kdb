## 3. 코드가 말해 주는 것의 한계

표본 50건 이상인 116개 코드를 일치율로 나누면:

| 구분 | 코드 수 | 뜻 |
|---|---|---|
| 세부유형까지 확정 (세부 일치율 ≥99%) | **46** | `tourapi_ko 39`→restaurant 99.9% 등 |
| 부모유형만 확정 (부모 ≥99%, 세부 <99%) | **38** | `aihub_tour 관광지`→location 99.9%이나 tourist_spot 은 94.6% |
| 보류 (부모 <99%) | **32** | `heritage_khs 21` 부모 57.8% — 종목코드는 장소 여부를 말하지 않는다 |

**여기서 성급할 뻔한 지점을 적어 둔다.** `tourapi_ko 12`(관광지)를 tourist_spot 으로 밀 뻔했다.
실제로는 이미 분류된 2,033건 중 **heritage 1,170 · nature 739** 로, 세부유형 일치율이 57.6%다.
코드는 "장소다"까지만 말하고 어떤 장소인지는 말하지 않는다.

## 4. ★ 가장 큰 덩어리 — `aihub_tour 편의오락` 94,024건

| | |
|---|---|
| 유형 미상 중 이 코드 | **94,024** (전체 미상의 82%) |
| TDB 가 분류한 적 있는 같은 코드 | **362** 뿐 |
| 그 362건의 부모 유형 | location **97.8%** (shopping 261 · restaurant 47 · accommodation 13 · tourist_spot 13 · district 10 …) |
| location 이 아니었던 것 | person 6 · event 1 · unknown 1 = **8건 (2.2%)** |

표본 실물: `제닉스아레나PC 배곧점 | 경기 시흥시 배곧3로 80`, `올레노래방 | 부산 사하구 장림번영로 36`.
**주소가 붙은 상업 시설이다.** 미상 106,602건 중 99.97%가 `addr_ko` 를 가지고 있다.

**세부유형은 줄 수 없다.** 362건이 shopping·restaurant·accommodation·tourist_spot 으로
흩어진다 — PC방·노래방·볼링장이 한 범주에 섞인 결과다. 하나로 밀면 그건 추측이다.

## 5. 운영자 결정이 필요한 것

**`편의오락` 94,024건을 `unknown` 에서 `location`(세부유형 NULL)으로 올릴 것인가.**

| 올린다 | 올리지 않는다 |
|---|---|
| 94,024건이 "범주 미상"에서 "장소, 세부 검수 대기"로 바뀐다 | 지금 상태 유지 |
| 근거: 코드 일치율 97.8%(표본 362) + 주소 보유 99.97% + 같은 원본 표의 음식점 145,433건을 이미 `location` 으로 흡수한 선례 | |
| 대가: 약 2%가 장소가 아닐 수 있다 — **1,900건 내외의 오분류** | 대가: 82%가 계속 "모름"으로 남는다 |

두 선택 모두 되돌릴 수 있다. 올리는 경우 분류 근거(코드·일치율·표본수)를 근거 행으로
남기므로 나중에 코드별로 골라 되돌릴 수 있다.

**46개 코드(세부유형까지 확정 가능)와 38개 코드(부모만)는 이 결정과 무관하게 적용 가능하다** —
근거가 충분하고, 대부분 이미 분류된 대상이라 미상 감소에 직접 기여하는 양은 작다.

## 6. 하지 않은 것

- API 문서 기억으로 코드 의미를 채우지 않았다. 전부 데이터에서 도출했다.
- 일치율이 낮은 코드를 "그럴듯하니까" 올리지 않았다.
- 세부유형 일치율이 99% 미만인 코드에 세부유형을 주지 않았다.
