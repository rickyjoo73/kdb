# 중국어(zh) — 번역 쪽에 건네는 현황

2026-09-17 기준. 활성 엔티티 **13,837행**.

## 1. 한 줄 요약

간체·번체 **오염은 0**이다. 채움률은 87%지만 **그중 36%가 기계번역**이고,
한자로 그럴듯하게 생겨서 눈으로는 구분되지 않는다. 그래서 값만 보지 말고
**`locale_provenance` 를 반드시 같이 보라.**

## 2. 칸 구조 — 두 언어다

| 칸 | 대상 | 채움 | 빈칸 |
|---|---|---|---|
| `canonical_zh` | 간체 · 중국 본토 | 12,083 (87.3%) | 1,754 |
| `canonical_zh_hant` | 번체 · 대만/홍콩 | 12,157 (87.9%) | 1,680 |

간체와 번체는 **서로 변환해서 쓰면 안 된다.** 기계 변환은 한국 성씨를 망가뜨린다 —
OpenCC 는 박(朴)을 樸 으로, 강(姜)을 薑 으로 바꾼다. 실제로 133건이 그렇게 오염돼
있었다. 필요한 칸을 그대로 받아 쓰고, 빈칸이면 빈칸으로 받아라.

## 3. 등급 — `locale_provenance` 는 묻지 않아도 붙는다

응답에 별도 파라미터 없이 항상 들어 있다.

```json
{ "canonical_zh": "柳成宰",
  "locale_provenance": { "zh": "wikidata-label", "zh_hant": "opencc" } }
```

| 라벨 | zh 건수 | 뜻 | 쓸 수 있나 |
|---|---|---|---|
| `operator-locked` | 83 | 오너가 직접 넣음 | 그대로 쓴다 |
| `wikidata-label` | 2,131 | 위키데이터 레이블 | 그대로 쓴다 |
| `external-db` | ~2,000 | TMDB·iTunes·Discogs 등 | 그대로 쓴다 |
| `media-consensus` | 소수 | 독립 매체 2곳 이상 일치 | 그대로 쓴다 |
| `wikipedia-langlinks` | 1,515 | 위키백과 언어링크 | 대체로 믿을 만함 |
| `opencc` | 796 | 우리가 자체 변환한 파생값 | 참고용 |
| `romanization` | 742 | 로마자 규칙 | 참고용 |
| **`machine-translation`** | **3,260** | **구글 번역** | **검증 전까지 쓰지 말 것** |
| `llm-only` | 1,108 | LLM 추측 | 검증 전까지 쓰지 말 것 |
| `llm-provisional` | (아직 0) | 근거 검색 실패 후 잠정 채움 | 무엇에든 밀린다 |

`verified_only: true` 를 주면 위 표의 상위 4개만 남고 나머지는 **빈칸으로** 온다.
«틀린 값보다 빈칸» 이 필요하면 이 스위치를 쓰면 된다.

## 4. 기계번역 3,260건이 왜 위험한가

라틴 문자로 오면 한눈에 보인다. 그런데 중국어는 아니다 — 전부 한자로 온다.

```
류성재 → 柳成宰     ← 한자가 실제로 맞다
리사코 → 丽莎科     ← 음만 딴 것. 실제 표기와 다를 수 있다
꽃의 비밀 → 花的秘密  ← 직역. 중국 공식 제목이 아니다
길 위에서 → 在路上    ← 직역
```

인명 1,367 · 노래/앨범 515 · 예능 319 · 등장인물 254 가 여기 해당한다.
**작품명은 특히 직역이라 공식 제목과 다를 가능성이 높다.**

## 5. 빈칸(1,754)은 그쪽 값을 써도 된다

오너 방침이다 — 우리가 못 채운 칸을 기다리느라 번역을 멈추지 말라.
그쪽에서 정한 표기를 쓰고, **우리에게 보내 달라.** 대조해서 판정한다.

- `POST /v1/observations` — 매체에서 관측한 표기. 독립 매체 2곳 이상이 같으면 승급한다.
- `POST /v1/corrections` — 우리 값이 틀렸다는 신고. 근거 URL 을 같이 주면 검증 큐로 간다.

우리 쪽 값과 다르면 셋 중 하나로 답한다:
① 우리가 근거 있는 값을 갖고 있다 → 근거와 함께 «우리 값이 맞다»
② 우리 값이 약한 등급이다 → 검증 큐 맨 앞으로 올린다
③ 우리가 빈칸이다 → 후보로 받는다

빈칸 타입별: 노래/앨범 407 · 인물 307 · 예능 299 · 그룹 193 · 소속사 123

## 6. 오늘 고친 것

| | 전 | 후 |
|---|---|---|
| 간체 칸에 번체 | 430 | **0** |
| 번체 칸에 간체 | 98 | **0** |

어젯밤에 «168 → 0» 이라 보고했는데 **틀렸다.** 그때 쓴 판정기가 손으로 고른 82자
정규식이라 그 목록에 있는 글자만 보고 있었다. OpenCC 사전 전체로 다시 재니 430건이
남아 있었다(全寶藍·鄭先哲·黄東赫 …). 판정을 사전에서 굽는 방식으로 바꿨다.

이체자 26건(昇·勛·啟·儁·製·裡·眞·嶋·讚)은 사전만으로 못 갈라서 세 모델
(gpt-5.6-sol · gpt-5.6-luna · gemma4)에 같은 프롬프트로 물어 대조하고 확정했다.
`昇` 은 본토 인명에서 그대로 쓰는 규범자라 유지했다(李昇基·姜昇希 …).

## 7. 아직 안 된 것

- **본토 매체 RSS 가 없다.** 번체는 대만 매체에서 ~200행이 들어오는데 간체는 0이다.
  `media-consensus` 로 승급할 재료가 간체 쪽에만 없다.
- **잠정 채움(`llm-provisional`) 은 꺼져 있다.** 빈칸 1,754를 LLM 으로 채우는 스위치인데,
  인명 한자를 어느 정도 맞히는지 소량으로 먼저 보고 열 예정이다.
