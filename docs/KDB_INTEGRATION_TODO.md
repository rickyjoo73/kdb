## 2. 변경하지 않을 방향

1. **목표 DB 구조를 먼저 설계하고, 검증한 구조에 필요한 TDB 데이터만 흡수한다.** 운영 KDB에 먼저 넣고 나중에 분리/정리하지 않는다.
2. 공통 Entity 원본은 KDB에 둔다. 정치·경제·스포츠용 독립 마스터 DB를 추가하지 않는다. Go 기반 운영을 유지한다.
3. 유형·세부유형·인물 직군/직업·뉴스 분야를 구분한다. 직업은 복수 가능하며 가수/배우/정치인마다 인물 테이블을 나누지 않는다.
4. 이름은 고유 키가 아니다. 같은 이름의 다른 사람/회사/장소/상품은 별도 UUID로 관리한다. 개명·직업/소속 변경 때 동일인의 UUID를 바꾸지 않는다.
5. UUID를 배정했다고 정체성 문제가 해결된 것은 아니다. 원본/기사 문맥·소속·활동·외부 식별자와 근거로 연결하고 불확실하면 보류한다.
6. 이름·프로필·관계·근거·보충 job·캐시는 정확한 Entity ID에 귀속한다. 동명 가수의 값을 배우의 빈칸에 복사하지 않는다.
7. 필요한 보호 규칙은 재사용한다. TDB 에이전트/레인/정찰 포털/과거 로그·통계/메뉴 전체를 KDB에 복제하지 않는다.
8. 전체 원본 조사, 복구용 보관, 운영 DB 적재는 다르다. 선별한다고 기존 유효 분야를 임의로 버리거나 원본을 삭제하지 않는다.
9. 분류 불명·근거 없음·권리 보류·생성값·fallback을 ‘기타/검증 완료/요청 언어 준비’로 숨기지 않는다.
10. UI는 공통 개요·고유명사·검수·보충·설정 중심이다. 이전/고급 진단은 운영자 도구로 분리하고 필요한 화면을 실제 기능과 함께 검증한다.

### 변경 통제

새 요청은 기존 목적에 추가되는지, 이전 결정을 대체하는지 먼저 기록한다.
필드/테이블/worker/메뉴 추가는 기획안의 U1~U5 사용처, 필요한 사례, 데이터 출처, 갱신 책임을 제시해야 한다.
범위 변경은 `변경 이유 → 영향 task ID → 선행/검증 영향 → 결정자·날짜`를 남긴 뒤 반영한다.
원칙을 바꾸는 요청·권리 변경·불명확한 동일인 병합·고위험 운영 변경은 사용자 또는 지정 책임자의 판단을 받는다.
작업 ID는 재번호화/재사용하지 않는다. 필요 없어진 항목은 완료 처리하지 않고 ‘범위 제외’ 사유와 대체 항목을 남긴다.
새 기능을 넣느라 이미 열려 있는 필수 안전성 작업을 삭제하지 않는다.

## 3. 실행·완료 기록 규칙

- 모든 `[ ]`는 아직 해당 단계의 완료 근거가 없다는 뜻이다. 기존에 비슷한 코드가 있어도 현재 계약으로 재검증하기 전 닫지 않는다.
- `[x]`는 그 항목의 산출물·검증 근거가 기록됐을 때만 사용한다. 설계/구현/격리 검증/운영 반영/관측 완료를 구분한다.
- 계획상 의존 관계가 있는 다음 단계는 앞 단계 게이트를 통과하기 전 시작하지 않는다. 게이트 실패 시 원인·재현·보정·재시험을 기록한다.
- 기술 작성/구현/검증 책임은 개발 담당이다. 정체성·권리·실사용 계약에 대한 미결 판단 책임은 사용자/지정 검수·운영 책임자로 구분한다.
- 날짜는 실측 후 산정한다. 기계 처리 시간, 수동 검수 적체, 외부 승인 대기는 별도로 보고한다.
- 소스·계정·권한·운영 DB 보호를 유지한다. KDB 산출물은 KDB 소유 작업 공간에 보관하며 사용자 수정 파일을 덮어쓰지 않는다.
- 배포 작업이 허용된 단계에서는 KDB 소유 변경 파일만 검토·검증·커밋/푸시하고 버전/복구점을 기록한다. TODO 작성 단계에서는 배포하지 않는다.

각 항목을 닫을 때 남길 기록:

```text
task_id / 상태(설계·구현·검증·운영·관측) / 실행일·담당
산출물 경로·코드 버전 / 테스트·실데이터 범위와 결과
변경 수량·분모 / 남은 보류·제외·오류 / 운영 영향·복구점
판단·승인 근거 / 다음 task_id
```

보고 단위는 이번에 완료한 task ID, 검증 결과, 미완료/보류, 다음 작업이다.
지표는 실제 준비율·오연결·미계상·재시도 비용을 포함하며 줄 수/등록 건수만 성과로 삼지 않는다.

- [ ] **P1.09** 전체 Go test/build·관련 race·복원 DB 통합 테스트·기존 API replay·390/1440px·권한/CSRF·조회 성능을 검사한다.
- [ ] **P1.10** 실패 사례를 설계/코드에 반영하고 재시험 근거를 기록해 G1을 인수한다. 테스트 전용 승인값을 운영에 넣지 않는다.

산출물: 격리 schema/코드, 재현 가능한 fixtures/시험, 전후 계약 비교, UI/성능 결과, 보정한 설계.
G1 통과: M01~M14의 DB/API 해당 범위와 필수 제약 통과, 동명 ID 사이의 표기/근거 교차 저장 0, 기존 보호/실사용 계약 회귀 없음.
금지: 테스트용 mock만으로 실제 DB 제약 통과 주장, 기존 코드가 있다는 이유로 생략, 운영 대량 이관.

### P2. 전체 조사·선별·선분류·변환 dry-run

- [ ] **P2.01** 조사 snapshot/schema/선택 정책/mapper 버전을 고정하고 19유형·locale·원천별 분모와 완전한 PK를 기록한다. QID 없는 기록도 조사한다.
- [ ] **P2.02** KDB의 기존 유형·primary/secondary_role·기각 사유와 TDB 원천 유형을 코드표에 선매핑한다. 추측·상충·비고유명사·권리 문제는 각각 보류/제외로 설명한다.
- [ ] **P2.03** 승인된 필드와 필요한 근거만 읽는 dry-run 변환기를 만든다. 0123 초안은 채택/수정/폐기를 판단하고 기능을 새 TODO 밖에서 실행하지 않는다.
- [ ] **P2.04** 원본/공통 ID, 이름·별칭, 필요한 지역/주소/좌표·소속, 출처/잠금의 전후값과 근거를 출력한다. 전체 원천 payload/과거 로그는 복사하지 않는다.
- [ ] **P2.05** 기존 TDB의 상점/음식점→역 오연결 2건과 파생 표기, KDB 이름 기반 legacy 인물 연결 등 알려진 위험의 교정/격리 계획을 작성한다.
- [ ] **P2.06** 격리 환경에서 batch 재실행·중단·중복·늦은 commit·삭제/병합·이름만 변경·잠금/정책 변경·역순 이벤트를 시험한다. 진행 원장과 원본 매핑의 누락을 검사한다.
- [ ] **P2.07** 포함/조건부/보관만/제외, 승인 범위 적재 예상/보류/실패를 원본 수와 대조하고 층화 표본 검수·처리량/메모리/저장 공간을 측정한다.
- [ ] **P2.08** 첫 운영 batch의 정확 대상·예상 변경·보호 규칙 선배포·중지 기준·복구·승인 책임을 기록하고 G2를 인수한다.

산출물: 조사/선별 manifest, 원본→목표 전후 diff, 정체성·권리 보류 목록, 격리 importer 검증, 운영 batch 계획.
G2 통과: 전체 조사 미계상 0, 승인 범위의 설명 없는 필드 손실 0, 표본 통과, 원자성/멱등성·복구 시험 통과, 필요한 운영 변경 승인 확보.
금지: 원장에 ID가 있다는 이유로 값 이관 완료 표시, 근거 없는 분류를 운영에 먼저 적용, raw 기록 전체 복제.

### P3. 승인 범위만 흡수·교정

- [ ] **P3.01** 변경 직전 운영 상태와 최신 백업/복원·여유 공간·기존 writer/잠금을 재확인하고 승인된 배포 버전·복구점을 기록한다.
- [ ] **P3.02** 필요한 schema/공통 보호 경로를 호환 배포하고 검증한다. 구 worker가 교정 전 값을 재설치할 수 있는 경우 보호/쓰기 차단을 먼저 적용한다.
- [ ] **P3.03** 승인된 소규모 batch만 반영한다. 정체성/이름 승인과 후보 수용을 분리하고 원본 UUID→공통 UUID 연결을 검증한다.
- [ ] **P3.04** 승인된 KDB 재분류·원본 오연결과 파생값 교정을 수행하고 실제 저장 결과·잠금·출처·다른 ID 영향 여부를 대조한다.
- [ ] **P3.05** 신규/수정/삭제/병합/정책/잠금 delta, 재실행, 중단·재개를 확인한다. 실패 batch는 격리하고 승인 범위를 임의 확대하지 않는다.
- [ ] **P3.06** 유형·locale·출처별 승인 범위를 차례로 확대하고 매 batch 원본 대조·준비/보류/오류·API 지연·재유입을 확인한다.
- [ ] **P3.07** 조사 분모와 승인 범위의 최종 처리/보류/제외를 공개하고 G3를 인수한다. UI의 등록 수를 검증 표기 수로 표시하지 않는다.

산출물: batch별 변경/검증/복구 기록, 원본 ID 추적, 실제 데이터 검색·비교, 분류·이름·권리 상태 집계.
G3 통과: 승인된 범위의 미계상/중복 처리/설명 없는 손실 0, 알려진 차단급 오연결의 신규 공급·재유입 0, 보류와 실제 사용 가능 수 명시.
금지: 전량 자동 승인, 이름 기준 일괄 병합, 원본 삭제, 실패를 숨기기 위한 분모 축소.

### P4. 필요한 자동 보충·갱신·분야 공급

- [ ] **P4.01** 기존 후보/Resolver/readiness/fill을 재사용해 미지 대상 발견과 기존 Entity의 언어 결손을 별도 처리한다. 알려진 이름이 있어도 같은 문장의 신규 동명을 놓치지 않는 입력 계약을 유지한다.
- [ ] **P4.02** 실제 필요한 여행 출처/표기 규칙만 공통 보충에 연결하고 남은 기존 공급 의존성을 목록화한다. TDB 레인/에이전트 시스템은 복제하지 않는다.
- [ ] **P4.03** 정치·행정의 인물/기관/정당/직책 원천을 한정 파일럿으로 인수한다. 권리·정체성·기간·locale 공급 근거를 확인한다.
- [ ] **P4.04** 경제의 기업/기업인 원천을 한정 파일럿으로 인수한다. 법인/브랜드/상품/임원 구분을 검증한다.
- [ ] **P4.05** 스포츠의 선수/지도자/팀/리그/대회 원천을 한정 파일럿으로 인수한다. 종목·선수 ID·소속/시즌을 검증한다.
- [ ] **P4.06** 사회·연예·문화의 기존 자산/실수요 보충을 인수한다. 가수/배우·실존/허구·학교/캠퍼스 등 구분을 검증한다.
- [ ] **P4.07** 새 출처/동일인/표기 근거에 따른 제한 자동 승인과 사람 검수 경계를 검증한다. 모델 confidence 하나로 승격하지 않으며, 원천 페이지/기사의 지시문은 신뢰할 수 없는 데이터로 취급해 도구 권한·정책을 변경하지 못하게 한다.
- [ ] **P4.08** 요청 locale의 준비, 근거/권리 철회 전파, no_evidence/no_form, 생성/번역/fallback 구분과 표기·ID·정책 버전을 실제 요청으로 확인한다.
- [ ] **P4.09** 원인별 재시도·취소·공정성·예산·잠금·오래된 lease/revision과 동일 입력 반복 억제를 실측한다.
- [ ] **P4.10** Gemma 호출 목적·스케줄·모델·시간/토큰·승인 변경/준비 증가를 기록하고 야간 사용 이유·무변경 비용을 기존 workflow에서 확인한다. 일정 변경은 별도 근거를 남긴다.
- [ ] **P4.11** 분야별 실제 수집/검수/언어 준비/실패 비용과 보호 정책 유지 결과를 기록해 G4를 인수한다. 분야 메뉴가 있다는 이유로 사용 준비를 주장하지 않는다.

산출물: 필요한 adapter/정책, 분야별 파일럿·정답 세트 결과, 실제 요청 준비 이력, 보충/작업 비용 지표.
G4 통과: 합의한 분야·locale·파일럿 범위에서 품질/준비/재시도 기준 충족, 미해결 원천/정체성/권리와 공급 제한 명시, 구 공급 경로를 끊어도 되는 범위 확인.
금지: 알려지지 않은 한자/공식명을 만들어 확정, 무제한 전체 LLM 재생성, 통계용 가짜 고객 요청을 실수요로 보고.

### P5. 실사용 API·단일 writer 전환

- [ ] **P5.01** 유지 대상 고객별 ID/조회/지역 힌트/표기/fallback/권한/변경 커서를 dual-read와 요청 replay로 대조한다. 필요한 변경은 계약/안내를 확정한다.
- [ ] **P5.02** 원본 source→공통 단일 writer의 cohort·epoch·DB 권한과 진행 job 배출/변경 기록/최종 delta 순서를 검증한다.
- [ ] **P5.03** 실패 시 복구를 연습한다. 전환 후 신규 쓰기가 있으면 보존·역변환 검증 없이 옛 DB/이미지로 단순 복귀하지 않는다.
- [ ] **P5.04** 최신 백업과 동결 기준점·delta 미처리/실패·고객 계약을 확인하고 승인된 범위부터 전환한다.
- [ ] **P5.05** 의존성이 해소된 구 writer/중복 보충만 종료한다. 필요한 수집 기능은 공통 제안 경로로 유지하며 자동 양방향 동기화를 남기지 않는다.
- [ ] **P5.06** KDB의 신규 등록/수정/직업 변경/표기 보충·기존 ID 조회가 단일 원본을 사용하는지 검증하고 G5를 인수한다.

산출물: 고객별 계약 비교, writer 전환/복구 기록, epoch/권한·구 worker 상태, 유지·제외 경로 목록.
G5 통과: 승인 범위의 이중 쓰기 0, delta 수렴/실사용 API 계약 충족, 새 쓰기 포함 복구 검증, 구 독립 writer의 재오염 경로 차단.
금지: 실사용 조사 없이 TDB 종료, 자격증명/세션 일반 복제, 승인 없이 원본/백업 삭제.

- [ ] **P7.03** Edipresso의 인증된 이벤트·중복/수정/취소·Recovery Sync와 기사 버전 계약을 연결한다.
- [ ] **P7.04** PressLocale 상태 원장+outbox/inbox·큐, 언어별 job·lease/heartbeat/fencing·재시도/DLQ를 검증한다.
- [ ] **P7.05** Gemma 3대 공통 worker pool·테넌트 공정성·우선순위·token budget·장문 처리와 모델/prompt 버전 추적을 검증한다. 서버당 6 동시는 실측 전 보장하지 않는다.
- [ ] **P7.06** HTML/URL/숫자/날짜/제목·본문/Entity 표기 validator와 제한 재번역·검수 전환을 구현한다.
- [ ] **P7.07** CMS 결과 반환·재전달, 구버전 결과의 최신 기사 덮어쓰기 방지, 승인된 자동/검수 발행·정정 정책을 검증한다.
- [ ] **P7.08** 실제 길이/언어 분포·피크·1대 장애·동명·정정·취소·재발행 E2E와 운영 지표를 인수한다.

## 6. 반드시 통과할 동명·분류·값 소유 시험표
